# v0.3.1 三轮代码结构重构与运行时边界更新报告

发布日期：2026-07-16

升级基线：`v0.3.0`

版本范围：Python/FastAPI 后端、SQLite 仓储、React 响应工作台、Cesium 独立工程、FRC-RAG 研究代码、自动化测试、验收审计与 CI。

## 1. 更新摘要

本版本按照“安全拆分、边界收敛、运行时隔离”三轮方案完成结构重构。150 条 OpenAPI 路径、兼容路径重写和响应闭环行为保持不变；主要变化是把超大文件拆为可独立维护的领域模块，并把研究实验、旧平台兼容能力与正式响应运行时明确分层。

本次重构不改变 Gate 结论。FRC-RAG 仍为 `NO-GO / SHADOW`，旧平台与 AgentTwin 兼容实现仍在 M7 退役门禁前保留，真实生产数据、基础设施、安全验收和岗位 UAT 仍属于外部条件。

## 2. 第一轮：安全拆分

### 2.1 应用工厂与路由

- `flood_system/api.py` 从 1087 行收敛为 129 行应用装配层，新增 `create_app()` 和惰性 `ApplicationRuntime`。
- OpenAPI 导出不再触发数据库初始化；测试可通过 `system_override` 注入隔离系统实例，不再修改模块级全局对象。
- 健康检查、就绪检查和指标拆到 `operations_router.py`；旧平台和 AgentTwin 路由分别进入独立兼容路由模块。
- `/response/*`、`/api/v1/*`、`/platform/*` 和 `/agent-twin/*` 的现有兼容入口继续保留。

### 2.2 前端与三维场景

- `ResponseWorkflowPage.tsx` 从 1218 行降至 479 行；面板、展示映射、文件准备和六类资源 API 分别进入 `features/response`。
- 文件 SHA-256、Base64 和上传载荷构造集中到单一实现，避免同一安全边界在页面内重复。
- `3D_visual/src/App.tsx` 从 1443 行降至 820 行；场景配置、类型、GLB 解析、坐标变换、相机和模型放置拆为独立模块。
- 主前端继续将约 4.73 MB 的 Cesium 运行时保持为独立异步块，没有重新并入同步入口。

### 2.3 测试结构

- 原 2218 行响应测试和 1521 行系统测试拆为 9 个业务域测试文件。
- 事件构造、模拟观测、失败网关和 API 客户端绑定集中在 `tests/support`。
- 最大的新领域测试文件为 731 行；24 场景验收引用同步到新的测试节点，防止“测试仍通过但验收证据失联”。

## 3. 第二轮：领域服务、仓储与端口边界

### 3.1 响应服务

- `ResponseWorkflowService` 保留原类名、导入路径和方法签名，32 行兼容门面组合事件核心、风险对象、证据、任务、文档、下发和运行维护七类实现。
- FRC 正式切流门禁、Baseline/Shadow 降级和证据冲突处理仍由原工作流入口执行，拆分没有绕过状态机、审批或审计。
- 新增 `ResponseWorkflowRepositoryPort`、`RagServicePort` 和 `SimulationGatewayPort`，服务层依赖从具体实现收敛为显式协议。

### 3.2 响应仓储

- `ResponseRepository` 保留 21 行兼容门面，持久化实现按核心、事件、任务、下发、文档、韧性和指标拆为七个模块。
- 现有加密、签名、不可变触发器、事务和幂等行为保持原接口兼容。
- 指标快照改为数据库聚合查询，避免按事件逐项加载完整对象和 N+1 查询；仍需解密的接管/STALE 载荷改为每类一次批量查询。

## 4. 第三轮：迁移、研究和兼容层隔离

### 4.1 有序迁移

- 新增校验和锁定的 `RepositoryMigration` 账本和 `0001_runtime_schema_baseline` 基线迁移。
- 启动迁移可重复执行；同版本迁移内容发生变化时失败关闭，禁止静默接受漂移的数据库定义。
- 新增迁移首次执行、幂等重跑和校验和篡改测试。

### 4.2 FRC-RAG 研究代码

- 9 个公开数据评测、消融和敏感性模块迁入 `research/frc_rag`。
- `research` 不进入 `flood_system*` 运行时 wheel，FastAPI 请求路径不携带研究依赖和实验入口。
- 12 个研究脚本加入源码树启动边界，既可继续使用 `python scripts/<entry>.py` 复现实验，又不要求把研究包安装为生产依赖。

### 4.3 旧系统兼容能力

- 旧平台实现迁入 `flood_system/compat/legacy_platform`，AgentTwin 迁入 `flood_system/compat/agent_twin`。
- `legacy_platform` 与 `agent_twin_compat` 成为明确属性；`production_platform` 与 `agent_twin` 作为兼容别名继续保留。
- M7 的真实旧流量归零、在途事件清理、归档恢复和旧账号/写权限撤销尚未完成，因此本版本只隔离，不删除兼容实现。

## 5. 功能与接口影响

- 没有删除正式响应功能，也没有改变任务、审批、反馈、证据冻结、Outbox、回调和事件关闭的业务语义。
- OpenAPI 仍包含 150 条路径；导出结果已按新版本重新冻结并通过确定性逐字节比较。
- FRC-RAG 仍只允许 `SHADOW`、`BASELINE_ONLY` 或人工复核路径；未通过 Gate 2 前不能切为正式默认检索。
- 兼容路由继续存在，但不能绕过 Core 响应状态机成为新的权威写入源。

## 6. 系统性能

本地受控环境为 Windows 单进程 FastAPI TestClient、加密 SQLite、可信身份和 nonce 防重放；以下数据只用于回归，不代表生产容量：

| API | P95 | 预算 | 错误率 |
|---|---:|---:|---:|
| 事件列表 | 12.193 ms | 150 ms | 0 |
| 事件总览 | 35.152 ms | 250 ms | 0 |
| 事件时间线 | 33.311 ms | 200 ms | 0 |
| 审计轨迹 | 36.695 ms | 300 ms | 0 |

四条受控路径均通过预算。指标端点的 SQL 聚合减少了对象构造和查询扇出，但本轮没有把该局部优化外推为生产吞吐提升；生产结论仍需 PostgreSQL、真实数据规模和并发压测。

## 7. 安全性与可靠性

- 迁移定义使用版本和 SHA-256 校验和锁定，内容漂移失败关闭。
- 就绪检查改用仓储公开 `health_check()`，不再从 HTTP 层调用私有连接方法。
- 研究代码和模型实验依赖退出运行时发行包，降低生产包攻击面和依赖耦合。
- 兼容代码进入明确命名空间，减少新代码误用旧写入路径的风险。
- 加密落盘、身份/RBAC/AAL2、幂等、审计链、模拟网关真实地址拒绝和 Gate 2 阻断保持有效。
- 本轮结构重构不能替代第三方渗透测试、生产 IdP/TLS/KMS、异地恢复和真实岗位 UAT。

## 9. 回滚与剩余边界

- 服务和仓储的原类名及导入路径均为兼容门面，应用版本回滚不要求删除新增数据库表或迁移账本。
- 新增迁移只追加账本记录，不执行破坏性降级；回滚时必须保留审计、幂等、任务和证据历史。
- 旧平台与 AgentTwin 只能在 M7 证据完整后退役，不能因目录已隔离而提前删除。
- Gate 2、权威预警/GIS/对象数据、生产 PostgreSQL、真实跨部门下发、双专家标注和生产安全验收仍未完成，不得把本次结构重构表述为生产上线完成。
