# v0.2.0 项目清理与结构重构更新报告

发布日期：2026-07-12

升级基线：`a89f188`

版本范围：Python 后端、主前端、Cesium 校准工具、测试、CI、文档和可复现验收产物。

## 1. 更新摘要

本版本不改变区县防办响应系统的业务边界，也不删除现行 `/response/*`、兼容 `/platform/*` 或 `/agent-twin/*` API。重点是清理已被 V3/渐进式合同取代的材料、拆分响应域单体辅助逻辑、修复确定性死代码和重复定义，并将静态质量检查纳入 CI。

版本号由 `0.1.0` 升级为 `0.2.0`。当前树以两份根目录设计文档、`PRODUCT.md`、OpenAPI 和 `docs/progressive_upgrade/` 为唯一现行事实源。

## 2. 功能与行为变动

### 2.1 响应工作流

- 将候选对象评分、EPSG:4326 点落多边形判断和风险对象构造拆到 `response_workflow/candidate_discovery.py`。
- 将反馈分类、去重键、资源/受阻替代建议、复盘建议和必需证据检查拆到 `response_workflow/feedback_policy.py`。
- `ResponseWorkflowService` 从 3205 行降至 3005 行，迁出 200 行领域辅助实现；HTTP 合同和存储合同保持不变。
- 新增独立领域策略测试，覆盖边界点判定、反馈分类优先级、去重稳定性、证据缺口和复盘建议。

### 2.2 LLM 网关

- 修复 `ResponsesLLMGateway.generate_regional_analysis_package` 被同名确定性实现覆盖的问题。
- 生产 Responses 网关现在按设计调用 `regional_analysis_package` Prompt Profile。
- 确定性区域分析实现移动到 `MockLLMGateway`，继续服务离线测试和演示降级。
- 新增网关归属回归测试，防止同名方法再次被静默覆盖。

### 2.3 前端

- 删除 1 个未消费的 `twinBusy` 展示层参数和 4 个未使用类型导入。
- 主前端和 Cesium 工具同时启用 `noUnusedLocals`、`noUnusedParameters`；新增死代码将直接导致 TypeScript 构建失败。
- 页面、路由、API 门面和用户操作流程没有删除或重命名。

## 5. 系统性能

环境：Windows 单进程 FastAPI TestClient、加密 SQLite、签名身份与 nonce 防重放；每条路径 5 次预热、40 次采样。该结果只用于仓库回归，不代表生产容量。

| API | v0.1 基线 P95 | v0.2 P95 | 变化 | 冻结预算 | 错误率 |
|---|---:|---:|---:|---:|---:|
| event list | 11.875 ms | 12.159 ms | +2.4% | 150 ms | 0 |
| event dashboard | 28.770 ms | 28.725 ms | -0.2% | 250 ms | 0 |
| event timeline | 26.953 ms | 27.842 ms | +3.3% | 200 ms | 0 |
| audit trail | 29.975 ms | 31.141 ms | +3.9% | 300 ms | 0 |

四条路径均远低于预算且错误率为 0；波动未形成可见性能回退。主前端生产输出约 5.35 MB、gzip 约 1.49 MB，其中 Cesium 运行时约 4.73 MB；独立 Cesium 工具约 4.22 MB、gzip 约 1.14 MB。Cesium 大块仍是后续性能优化项，但本版本没有扩大该依赖面。

Docker 构建同时排除本机未跟踪的 GLB（约 183 MB）和 PBF 原始下载，前端构建上下文由 193.05 MB 降至 889.86 kB（约减少 99.5%），并保持与 GitHub 构建一致；模型仍按 `3D_visual/public/models/README.md` 的外部资源方式提供。
