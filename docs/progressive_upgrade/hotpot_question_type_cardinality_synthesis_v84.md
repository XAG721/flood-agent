# HotpotQA 问题类型感知证据基数前瞻验证（v84）

## 结论

v84 在预注册的“完整证据召回率不低于 `0.62`”安全约束下，建立了问题类型感知 3/4 条证据基数控制的同数据集、案例互斥双阶段支持。开发和确认各 600 例、各含 400 个 bridge 与 200 个 comparison，二者及 2,600 个模型开发 ID 零重叠；两阶段均一次性通过全部 18 项严格门。

最终状态为：

`HOTPOT_V84_CARDINALITY_CASE_DISJOINT_CONSTRAINED_ADVANTAGE_ESTABLISHED`

这不是对所有控制组的无条件原始 F1 优势。固定前 3 条控制在两个阶段都取得最高原始 F1，但完整证据召回只有 `0.571667`，未达到预注册安全下限，因此只从安全约束内的主比较排除，仍在全部结果中完整披露。选择器采用、CANARY、DEFAULT 和生产均不授权，Gate 2 继续为 `NO-GO/SHADOW`。

## 冻结机制与模型选择

v84 完全复用冻结的 `graph_gbr_soft_override_router_v76` 路由与证据顺序，只在其输出之后增加一个问题文本分类器：comparison 概率不低于 `0.3` 时保留前 3 条，否则保留前 4 条。运行时不读取官方题型、答案或 gold。

模型开发只使用永久排除的 2,600 个已暴露 HotpotQA 案例：1,000 条历史、v76 开发 800 条和 v76 确认 800 条。有限搜索包含 16 个哈希逻辑回归配置和 112 个分类阈值策略；五折交叉拟合选择哈希维度 `512`、L2 `32.0`、阈值 `0.3`。交叉拟合候选 F1/完整证据召回为 `0.657218/0.645385`，相对固定前 4 条提高 `+0.027613`，95% CI `[+0.024012,+0.031077]`；该结果参与选型，不是前瞻确认。

在选择任何 v84 目标 ID 前，协议、来源登记、模型、两个实现模块、两个运行器和两个测试文件均已进入九文件 SHA-256 锁。目标源共有 7,405 条；排除 2,600 条后尚余 bridge 4,315 条、comparison 490 条，因此预注册开发/确认各取 `400/200`，两阶段结束仍保留 3,515/90 条未触碰容量。

## 可支持与不可支持的主张

v84 支持：问题文本可以在不改变冻结 v76 路由和排序的前提下，稳定选择 3/4 条证据基数；在完整证据召回不低于 `0.62` 的预注册约束下，两组案例互斥 HotpotQA 目标都显著优于最强安全合格控制，并减少平均上下文 token。

v84 不支持：无条件击败固定前 3 条的原始 F1、独立数据集泛化、官方 HotpotQA 排行榜、答案生成正确性、真实 SetR 对比、洪水领域专家有效性、选择器采用或生产放行。

开发与确认共 1,200 个目标 ID 必须永久排除于后续模型、阈值、门槛或策略选择。HotpotQA comparison 未触碰容量只剩 90 条，不能再复制同规模双阶段设计；下一步应转向新的独立公共数据集或预先登记不同的样本结构，而不能复用 v84 目标。
