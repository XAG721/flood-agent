## Gate 判定

- Gate 0：`GO（受控模拟）`。来源、版本、种子、数据来源、模拟标记、家族隔离及 24 场景八类验收字段均由测试校验。
- Gate 1：`GO（受控模拟）`。当前规则候选链达到建议阈值，仍强制人工确认。
- Gate 2：`NO-GO`。内部 3 条工程集只证明选择逻辑可运行；ConditionalQA、MultiHop-RAG、HotpotQA 的 Evidence F1 配对区间均未显著为正，CONFLICTS 上 FRC Accuracy 低于覆盖贪心代理且区间跨 0。9/9 命名消融已有执行工件，但 Full 未优于 `w/o Role` 或 `w/o Conflict`；HousingQA Full 虽优于 `w/o Field`，却与最强字段基线持平且回答准确率低；LawShift 与 EUR-Lex Full 均改善无适用性过滤版本，却与获得相同元数据的公平过滤基线持平。K、Token、缺失、分块、冲突阈值和字段/角色权重技术矩阵已完整，但无稳定优势；HousingQA 权重扫描是跨领域事后诊断，真实防汛领域双专家与 expected-behavior adherence 独立评判仍未完成。此前的 `setr` 仅是覆盖贪心代理，不是真实 SetR。系统默认保持 `SHADOW`，重新通过 Gate 2 后才可考虑 `CANARY/DEFAULT`。
- Gate 3：`GO（自动化安全不变量）`。未审批、越权、非法迁移、职责分离、证据/规则/审批/下发哈希、幂等 Outbox 和通用写请求幂等账本有自动测试；后者覆盖原响应重放、同键异请求、并发预留、4xx 修正重试、异常不确定态、加密存储与密钥轮换。
- Gate 4：`CONDITIONAL NO-GO`。受控业务闭环、本地恢复、进程内 API 冻结预算和三套已知依赖漏洞审计通过，但生产网络/并发性能预算、真实 IdP/TLS/KMS、异地主机恢复与第三方渗透测试尚无外部运行证据。
