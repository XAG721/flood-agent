# MuSiQue-Full 跨域 RoBERTa 支持门验证（v65）

## 1. 结论

v65 将 v64 只在 SQuAD 2.0 train 学得的单一 `null-vs-span` 精确阈值 `0.974609375` 原样迁移到 MuSiQue-Full，在目标数据上学习或调整的参数为 0。600 条修正后冻结样本的支持判断平衡准确率为 `0.563333`，答案通过率为 `0.630000`，无答案拒绝率为 `0.496667`，未达到预注册的 `0.80/0.80/0.70` 门槛。

因此状态冻结为：

`MUSIQUE_FULL_V65_ROBERTA_TRANSFER_SUPPORT_NOT_ESTABLISHED_STOP_BEFORE_RETRIEVAL`

按预注册停止规则，query 生成与 BGE/reranker 检索评分均未启动，不能形成 v65 的 FRC 与非 FRC 检索效用对比。v65 样本不得用于阈值、门槛、样本或选择器后验调整；选择器、CANARY、DEFAULT 均不授权，Gate 2 保持 `NO-GO/SHADOW`。

## 2. 数据、模型与独立性边界

- 目标文件为官方 MuSiQue 仓库 revision `922ac98f19a201998dbdae6d7f2887a5258dbdeb` 对应的 `musique_full_v1.0_train.jsonl`，文件 SHA-256 为 `b1cd998f7e0e2838d6fda024e4ad1eb0e7fc3edefdadb0bd9b5b10b0907f2034`，许可为 CC BY 4.0。
- 上游文件名虽为 `train`，在 v65 中只承担一次性跨域机制确认角色，不用于训练或调参。
- 官方 README 明示 MuSiQue 由 SQuAD、T-REx、Natural Questions、MLQA 和 Zero Shot RE 等种子问题组合而成；支持模型 `deepset/roberta-base-squad2` 又在 SQuAD 2.0 上训练。因此 v65 在采样前排除了组合问题或任一分解问题与 SQuAD 2.0 train 规范化题面精确相同的 5,388 行。
- 精确题面排除不能证明不存在释义、上下文或预训练重叠，故 v65 明确不声明“严格独立模型训练确认”，也不是官方 MuSiQue 榜单结果。
- v36 只使用 `musique_ans_v1.0_dev.jsonl`；v65 与 v36 来源 ID 重叠为 0，未复用 v36 的逐例问题、查询、分数或结果。

## 3. 冻结协议与盲执行

协议、来源、模型和初始实现均在首次解析目标 JSONL 前登记。固定规则如下：

1. 答案/无答案各抽取 300 条，每个来源 ID 最多保留一条；
2. 每个官方段落独立形成一个 QA 输入，盲缓存不包含 answerability、答案、别名、分解答案、supporting 标记或 gold hop count；
3. 每段使用 v64 固定模型和固定阈值计算合法 span 相对 CLS null 的 margin；案例 margin 为全部段落有限 margin 的最大值；
4. 仅当案例 margin 严格大于 `0.974609375` 时判为有支持；
5. 只有全部 pre-retrieval 支持检查通过，才允许 query 与神经检索评分。

修正后样本包含 600 个唯一来源 ID、11,999 个段落 QA 输入；答案状态各 300，最少/最多段落数为 19/20，QA 无效案例数为 0。gold 只在 11,999 条固定 QA 输出全部完成后连接。

## 4. 指标计算前发现的完整性问题及处置

初始实现错误地按答案状态分别选取 MuSiQue-Full 的配对变体。由于答案与无答案变体复用相同来源 ID，600 条准备记录实际只有 300 个唯一来源 ID，违反“每个来源 ID 最多一条”的协议不变量。

该问题通过行数、唯一 ID 数与工件哈希发现；发现时未读取预测 margin、span 或支持判定值，未连接 gold，未计算总体或分层指标，也未启动 query 或神经检索。初始运行被永久标记为：

`MUSIQUE_FULL_V65_PROCEDURAL_INVALID_DUPLICATE_SOURCE_ID_STOP_BEFORE_METRICS`

修正只做程序性完整性恢复：以预先固定的 SHA-256 奇偶规则把每个来源 ID 分配到唯一答案状态，再按新的固定盐排序；同时排除无效运行已经产生 QA 输出的全部 300 个来源承诺。模型、权重、阈值、support 公式和门槛均未改变。修正运行使用独立缓存和独立执行登记，与无效运行来源承诺重叠为 0。无效运行的 QA 输出永不用于指标、调参、选择或报告结论。

## 6. 失效机制解释

v64 的阈值在同域 SQuAD 2.0 闭段落持出集上有效，但不能直接转化为跨 19—20 个段落的多跳链完整性判定。v65 对所有段落取最大有限 margin，且刻意不做多重比较校正；段落数增加会扩大遇到高置信局部 span 的机会。即使关键推理链已经断裂，非 supporting 段落仍可能包含与问题表面匹配的实体或答案片段，于是案例被误判为“支持充分”。

该解释与局部 span 陷阱拒绝率仅 `0.449275`、2-hop 无答案拒绝率仅 `0.476987` 一致，但它仍是对冻结结果的机制解释，不是新模型或新门控方案的有效性证明。

## 7. 可支持与不可支持的陈述

v65 支持以下陈述：

- 单一 SQuAD2 null-vs-span 阈值不能不加校正地充当 MuSiQue-Full 多段落、多跳证据完整性门；
- “存在一个高置信局部 span”不等于“完整多跳证据链成立”；
- pre-retrieval 停止门能在支持判断不足时阻止昂贵检索比较和后验选型。

v65 不支持以下陈述：

- 不构成官方 MuSiQue 排名、答案生成或开放语料检索结果；
- 不构成真实 SetR 复现或 FRC-RAG 相对检索基线优劣结论；
- 不构成严格独立模型训练确认、洪水领域专家验证或生产放行证据；
- 不能根据本结果在 v65 样本上修阈值、加多重比较校正、换聚合器或重新采样后再宣称确认。

后续若研究链完整性判断，应使用新的、承诺互斥的数据与预注册方案，显式建模跨段证据覆盖、关系链一致性或多重比较，而不是修补 v65 的冻结结果。
