# MuSiQue 同域竞争桥接实体支持门实验（v72）

## 1. 结论

v72 检验一个在选择样本前冻结的机制假设：如果多跳答案确实依赖上游预测出的桥接实体，那么同一个冻结 QA 模型在下游问题中应当更支持事实桥接实体，而不是它从另一候选段落中选出的高 margin、归一化内容不同的同域竞争 span。

开发集上，15 特征候选的答案通过率、无答案拒绝率和平衡准确率分别为 `0.617500/0.795000/0.706250`。最强公平基线和最强既有特征控制均为九信号线性控制，指标为 `0.612500/0.802500/0.707500`。候选相对它的同例正确性差值为 `-0.001250`，10,000 次 bootstrap 的 95% 区间为 `[-0.015000,+0.012500]`。

候选相对六特征同域竞争信号单独控制提高 `+0.112500`，95% 区间为 `[+0.080000,+0.146250]`。这证明九个既有基础特征携带重要信息，但不能证明六个同域竞争桥特征在既有特征之上提供增量。候选还未达到 `0.72` 平衡准确率和 `0.80` 无答案拒绝率门槛，并出现 1 个按协议保留和 fail-closed 的无效特征输出。因此 v72 的预注册机制支持未建立，状态冻结为：

`MUSIQUE_V72_IN_DOMAIN_RIVAL_DEVELOPMENT_SUPPORT_NOT_ESTABLISHED_STOP_BEFORE_CONFIRMATION`

确认集不打开，选择器和检索评分不采用该方法，CANARY 与 DEFAULT 均未授权，Gate 2 保持 `NO-GO/SHADOW`。

## 2. 冻结边界与隔离

- 数据为官方 MuSiQue revision `922ac98f19a201998dbdae6d7f2887a5258dbdeb`，许可证为 CC BY 4.0。
- v72 只使用 v71 聚合结论提出不同机制，没有读取 v71 个案预测、错误、特征或分组来选择 v72 特征、模型、优化器、阈值或门槛。
- 协议、六个同域竞争特征、135 个学习标量、全部对照、阈值规则、bootstrap 种子及门槛均在选择任何 v72 样本前冻结。
- 永久排除 v65–v71 共 12,100 个唯一历史来源承诺；开发集再排除 1,600 个 v72 校准来源承诺。
- 校准集为 800 条可回答和 800 条不可回答样本，开发集为 400/400；与历史/校准来源及 SQuAD2 规范化精确题面重叠均为 0。
- 校准集 2/3/4-hop 分布为 `1178/343/79`，开发集为 `610/163/27`。
- 校准和开发的直接段落 QA 行数分别为 `31,998` 和 `16,000`。全部事实链 hop 的 blocked 数均为 0；开发集形成 1,016 个固定哨兵转换和 1,016 个同域竞争转换。
- 官方分解只提供问题模板与顺序。链的桥接实体来自冻结 QA 模型的上游预测，不使用分解答案、`paragraph_support_idx` 或 supporting 标记。因此这仍是 oracle 计划组件实验，不是自动分解结果。

## 3. 方法与公平控制

每个事实链 hop 先在相同的有序候选段落中运行冻结 QA 模型。对于每个上游事实 hop，从另一段落中选出 margin 最高、非空且归一化 span 不同的竞争 span。每个下游 `#k` 依赖生成一个竞争查询：只把目标 `#k` 替换为其竞争 span，其余占位符全部替换为事实链预测。查询仍在相同段落、相同模型、相同 QA 参数和相同 tie-break 规则下执行。

六个新特征均限制在 `[0,1]`，并在学习模型中施加非负单调约束：

1. `rival_dependency_coverage_fraction`
2. `rival_margin_advantage_min`
3. `rival_margin_advantage_mean`
4. `rival_factual_win_fraction`
5. `rival_paragraph_change_fraction`
6. `rival_span_change_fraction`

候选由 v68 的九个基础特征加六个同域竞争特征组成，共 15 维。为避免把数据批次差异误认为方法差异，v72 还在同一校准集上重新拟合 v71 固定哨兵控制。公平比较包括校准直接问题、固定 v66 完整链、校准链瓶颈、九信号线性控制、v69 27 特征加性控制、v69 32 特征交互控制、v70 15 特征段落竞争控制、v71 15 特征固定哨兵控制，以及六特征同域竞争信号单独控制。全部报告方法合计只从校准集学习 135 个标量。

## 4. 实现勘误

首次执行校准 QA 时，直接问题和第一跳事实模型输出已经完成，但程序在写入竞争 span 目录前停止。注册 verifier 的 `span_sha256` 对应 tokenizer offset 指定的原始 context 切片，其中可能包含边界空白；v72 实现却先对切片执行 `strip()` 再验证哈希，因此在 31,998 条第一跳段落输出中产生 97 个错误不匹配。按原始 offset 切片验证时不匹配数为 0。

正式勘误改为先验证未裁剪原始切片的哈希，再对用于非空、归一化差异检查和下游查询的 span 进行裁剪。竞争 span 的排序和资格规则没有变化。失败发生在事实 hop 2–4、任何固定哨兵或竞争反事实输入、特征决策、金标拼接和指标计算之前。修正后新增 `test_rival_catalog_validates_raw_offset_hash_before_trimming`，17/17 项合成测试通过；协议、样本、特征、模型、优化器、阈值、门槛、阶段规模和 135 个学习标量均未改变。

## 6. 解释与后续约束

同域竞争信号单独控制明显弱于完整候选，说明主要预测能力来自九个基础链支持特征。新增竞争桥特征在开发集上没有超越九信号线性控制，也没有改善同数据固定哨兵控制所代表的既有反事实方向。候选与最强控制只相差一个案例量级，置信区间跨越零，无法建立稳定增量。

这只否定本次预注册的“另一段落最高 margin 竞争 span + 单依赖替换 + 六个有界单调统计量 + 九基础特征线性组合”，不能推断所有桥接反事实方法无效。1 个无效案例也表明冻结抽取式 QA 仍可能在直接问题或事实 hop 上不给出有效 span；协议正确地把它保留并 fail-closed，但零无效率门槛因此失败。

v72 的 2,400 个校准/开发案例不得再用于筛选竞争 span 规则、特征、模型、阈值或门槛后声称确认。若继续研究，必须提出不同且可证伪的机制，永久排除 v65–v72 已用来源，并在选择任何新样本前重新冻结实现和公平对照。

## 7. 结论边界

v72 不构成自动分解能力、官方 MuSiQue 答案或排行榜结果、FRC 检索效用、真实 SetR 复现、严格独立模型训练、洪水领域专家评测或生产放行证据。确认集、检索评分、选择器采用、CANARY 和 DEFAULT 均未授权，Gate 2 继续为 `NO-GO/SHADOW`。
