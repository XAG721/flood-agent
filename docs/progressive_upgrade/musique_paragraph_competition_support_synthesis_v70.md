# MuSiQue 段落竞争稳定性支持门实验（v70）

## 1. 结论

v70 检验一个预先冻结的机制假设：真正得到段落支持的问题，其最高分段落相对其他段落应形成更稳定的竞争优势。实验从冻结 QA 模型的逐段 `null-vs-span` margin 中提取 top-1/top-2 差距和固定温度 softmax 质量，并分别对直接问题及 2–4 跳链做最小值、均值聚合。

开发集上，15 特征候选的答案通过率、无答案拒绝率和答案可回答性平衡准确率为 `0.572500/0.757500/0.665000`。最强公平基线和最强既有特征控制均为 v69 单调交互控制，指标为 `0.600000/0.782500/0.691250`。候选相对它的同例正确性差值为 `-0.026250`，10,000 次 bootstrap 的 95% 区间为 `[-0.048750,-0.003750]`；独立的既有特征控制区间为 `[-0.048750,-0.004969]`。

候选相对六特征竞争信号单独控制提高 `+0.096250`，95% 区间为 `[+0.060000,+0.132500]`，说明既有基础特征包含重要信息，但不能证明新增竞争信号提供增量：候选还比九信号线性控制低 `0.001250`。因此 v70 的预注册段落竞争机制支持未建立，状态冻结为：

`MUSIQUE_V70_PARAGRAPH_COMPETITION_DEVELOPMENT_SUPPORT_NOT_ESTABLISHED_STOP_BEFORE_CONFIRMATION`

确认集不打开，选择器和检索评分不采用该方法，CANARY 与 DEFAULT 均未授权，Gate 2 保持 `NO-GO/SHADOW`。

## 2. 冻结边界与隔离

- 数据为官方 MuSiQue revision `922ac98f19a201998dbdae6d7f2887a5258dbdeb`，许可为 CC BY 4.0。
- v70 只使用 v69 聚合结论来提出新假设，没有读取 v69 个案预测、错误、特征或分组来选择 v70 特征、模型、优化器或门槛。
- 协议、六个竞争特征、101 个学习标量、对照组、阈值规则、bootstrap 种子及全部门槛均在选择任何 v70 样本前冻结。
- 永久排除 v65–v69 共 7,300 个唯一历史来源承诺；开发集再排除 1,600 个 v70 校准来源承诺。
- 校准集为 800 条可回答和 800 条不可回答样本，开发集为 400/400；与历史/校准来源及 SQuAD2 规范化精确题面重叠均为 0。
- 校准集 2/3/4-hop 分布为 `1186/336/78`，开发集为 `599/161/40`。
- 官方分解只提供问题文本和顺序，不提供分解答案、`paragraph_support_idx` 或 supporting 标记；因此这仍是 oracle 计划组件实验，不是自动分解结果。

## 3. 方法与公平控制

每个问题先在全部有效段落 margin 上计算两个固定统计量：

1. `top1_top2_gap_scaled = clip(top1 - top2, 0, 10) / 10`；
2. 固定温度 `1.0` 的 top-1 softmax 质量。

六个新特征依次为直接问题的两项统计、链内 gap 的最小值/均值、链内 softmax 质量的最小值/均值。候选由 v68 的九个基础特征加六个新特征组成，共 15 维。所有竞争特征的学习系数投影为非负；只有 3-hop/4-hop 指示和截距不受非负约束。

公平比较包括：校准直接问题、固定 v66 完整链、校准链瓶颈、同一 v70 校准数据和同一优化器拟合的九信号线性控制、v69 27 特征加性控制、v69 32 特征交互控制，以及六特征竞争信号单独控制。全部报告方法合计只从校准集学习 101 个标量。

## 4. 实现勘误

首次执行 `prepare --stage calibration` 时，runner 把 SQuAD2 文件路径直接传给需要已解析 JSON 的精确问题排除函数，因而在目标数据迭代、样本选择、模型运行和指标计算前以 `AttributeError` 停止；没有创建任何 v70 缓存或结果。

正式勘误只把已登记 SQuAD2 文件按 UTF-8 解析为 JSON 后再传入排除函数，并增加对应回归测试。修正后 17/17 项合成测试通过；协议、样本盐、特征、模型、优化器、阈值、门槛和 101 个学习标量均未改变。原始实现登记和修正后哈希链均保留在 `musique_paragraph_competition_support_implementation_erratum_v70.json`。

完整性门槛中，样本数、答案状态平衡、结构排除率、来源隔离和 SQuAD2 精确题面隔离通过。两个同源配对案例在第 2 跳产生空预测 span，按冻结规则保留并 fail-closed，导致无效输出率不为 0；没有删除或替换案例。

以下正式门槛失败：

- 无效输出率必须为 0；实际为 `2/800`；
- 平衡准确率 `0.665000 < 0.72`；
- 答案通过率 `0.572500 < 0.60`；
- 无答案拒绝率 `0.757500 < 0.80`；
- 相对最强公平基线 `-0.026250 < +0.05`，且区间上界也低于 0；
- 相对最强既有特征控制 `-0.026250 < +0.02`，且区间上界也低于 0；
- 2-hop 无答案拒绝率 `0.742574 < 0.75`。

3-hop 和 4-hop 无答案拒绝率分别为 `0.789474` 和 `0.857143`。相对竞争信号单独控制的增益及其正区间通过，但所有门槛必须同时通过，不能抵消其他失败项。

## 6. 解释与后续约束

这组固定段落竞争统计本身携带一定可回答性信息，但在九个基础特征上加入它们没有提高开发集性能，并且显著落后于既有交互控制。该结果只否定本次预注册的 margin-gap/softmax-mass 特征组合，不能推广为“所有检索竞争或不确定性特征均无效”。

v70 的 2,400 个校准/开发案例不得用于追加或筛选竞争统计、温度、归一化方式、模型、阈值或门槛后再声称确认。若继续研究，必须先提出不同且可证伪的机制，永久排除 v65–v70 已用来源，并在选择任何新样本前重新冻结实现和公平对照。

## 7. 结论边界

v70 不构成自动分解能力、官方 MuSiQue 答案或排行榜结果、FRC 检索效用、真实 SetR 复现、严格独立模型训练、洪水领域专家评测或生产放行证据。确认集、检索评分、选择器采用、CANARY 和 DEFAULT 均未授权，Gate 2 继续为 `NO-GO/SHADOW`。
