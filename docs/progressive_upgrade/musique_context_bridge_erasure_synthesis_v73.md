# MuSiQue 上下文桥接实体擦除支持门实验（v73）

## 1. 结论

v73 检验一个在选择样本前冻结、区别于 v71/v72 问题侧替换的机制：保持完全事实化的下游问题不变，只把全部候选证据上下文中有界、大小写不敏感的桥接实体精确提及替换为注册 RoBERTa tokenizer 已知的 `<mask>`，测量事实证据保留相对证据擦除造成的 margin、获胜段落和答案 span 变化。

开发集上，15 特征候选的答案通过率、无答案拒绝率和平衡准确率分别为 `0.587500/0.817500/0.702500`。最强公平基线和最强既有特征控制均为在同一 v73 校准集上重新拟合的 v72 同域竞争桥控制，其指标为 `0.610000/0.795000/0.702500`。候选相对它的同例正确性差值为 `0.000000`，10,000 次 bootstrap 的 95% 区间为 `[-0.013750,+0.013750]`。

候选相对六特征擦除信号单独控制提高 `+0.138750`，95% 区间为 `[+0.103750,+0.175000]`。这说明九个既有基础特征携带主要判别信息，但不能证明六个上下文擦除特征在既有特征之上提供增量。候选还未达到 `0.72` 平衡准确率和 `0.60` 答案通过率门槛。因此 v73 的预注册机制支持未建立，状态冻结为：

`MUSIQUE_V73_CONTEXT_BRIDGE_ERASURE_DEVELOPMENT_SUPPORT_NOT_ESTABLISHED_STOP_BEFORE_CONFIRMATION`

确认集不打开，选择器和检索评分不采用该方法，CANARY 与 DEFAULT 均未授权，Gate 2 保持 `NO-GO/SHADOW`。

## 2. 冻结边界与隔离

- 数据为官方 MuSiQue revision `922ac98f19a201998dbdae6d7f2887a5258dbdeb`，许可证为 CC BY 4.0。
- v73 只使用 v72 聚合结论提出证据侧干预，没有读取 v72 个案预测、错误、特征或分组来选择 v73 特征、模型、优化器、阈值或门槛。
- 协议、六个擦除特征、152 个学习标量、全部同数据对照、阈值规则、bootstrap 种子和门槛均在选择任何 v73 样本前冻结。
- 永久排除 v65–v72 共 14,500 个唯一历史来源承诺；开发集再排除 1,600 个 v73 校准来源承诺。
- 校准集为 800 条可回答和 800 条不可回答样本，开发集为 400/400；与历史/校准来源及 SQuAD2 规范化精确题面重叠均为 0。
- 校准集 2/3/4-hop 分布为 `1198/315/87`，开发集为 `587/174/39`。
- 校准和开发的直接段落 QA 行数分别为 `31,995` 和 `16,000`。开发集全部事实 hop 的 blocked 数为 0。
- 官方分解只提供问题模板与顺序。链的桥接实体来自冻结 QA 模型的上游预测，不使用分解答案、`paragraph_support_idx` 或 supporting 标记。因此这仍是 oracle 计划组件实验，不是自动分解结果。

## 3. 方法与公平控制

事实链完整运行后，对每个下游问题中的每个唯一 `#k` 依赖单独构造一次证据侧干预。问题中的所有占位符仍替换为事实链预测；只有上下文中与目标桥接 span 大小写不敏感精确匹配、且两侧满足字母数字边界的非重叠提及被替换为 `<mask>`。段落顺序、模型、最大长度、stride、最大答案长度和 tie-break 规则保持不变。

六个新特征均限制在 `[0,1]`，并在学习模型中施加非负单调约束：

1. `erasure_dependency_coverage_fraction`
2. `erasure_margin_drop_min`
3. `erasure_margin_drop_mean`
4. `erasure_factual_win_fraction`
5. `erasure_paragraph_change_fraction`
6. `erasure_span_change_fraction`

候选由 v68 的九个基础特征加六个擦除特征组成，共 15 维。公平比较包括校准直接问题、固定 v66 完整链、校准链瓶颈，以及在同一 v73 校准集上重新拟合的九信号控制、v69 加性与交互控制、v70 段落竞争控制、v71 固定哨兵控制、v72 同域竞争桥控制和六特征擦除信号单独控制。全部报告方法合计只从校准集学习 152 个标量。

协议额外要求开发集平均依赖覆盖率至少为 `0.50`。未命中的依赖不会被删除，而是保留在覆盖分母中并产生零干预向量。

## 4. 实现勘误

首次执行校准 prepare 时，程序完成注册文件哈希验证后、解析任何目标行之前停止。来源校验器把 15 个 prior-map `Path` 对象直接传给只接受已解码 JSON 行对象的继承函数，触发 `AttributeError: 'WindowsPath' object has no attribute 'get'`。

正式勘误改为逐个以 UTF-8 JSONL 打开已注册 prior map，把非空行解码为对象后传给承诺加载函数，并对 15 个结果取并集。修正没有改变来源哈希、承诺期望、协议、样本、擦除规则、特征、模型、优化器、阈值、门槛、阶段规模或 152 个学习标量。新增回归测试 `test_registered_prior_paths_are_loaded_as_jsonl_rows`，修正后 19/19 项无目标数据合成测试通过。

## 6. 解释与后续约束

上下文擦除候选与最强同域竞争桥控制取得相同平衡准确率，但形成不同的安全性取舍：候选的答案通过率降低 `2.25` 个百分点，拒绝率提高 `2.25` 个百分点。证据擦除信号因而可以改变决策边界的保守程度，却没有增加总正确性，置信区间也不能排除负增益。

几乎完整的擦除覆盖证明失败不是由精确提及稀疏造成。擦除信号单独控制明显弱于完整候选，说明主要能力仍来自既有九个基础链支持特征。开发集零无效输出也排除了 v72 单个 fail-closed 案例对本轮结论的解释。

这只否定本次预注册的“有界精确提及 + `<mask>` 上下文替换 + 六个有界单调统计量 + 九基础特征线性组合”，不能推断所有证据侧因果干预无效。v73 的 2,400 个校准/开发案例不得再用于筛选匹配规则、替换 token、特征、模型、阈值或门槛后声称确认。

若继续研究，必须提出不同且可证伪的机制，永久排除 v65–v73 已用来源，并在选择任何新样本前重新冻结实现和公平对照。由于训练 split 在排除 v73 校准后只剩 `544/599` 个分组候选，本轮之后仍可支持一次 400/400 开发集，但后续同规模校准/开发迭代的训练来源容量将显著收紧；继续扩展应优先注册新的独立公开数据源，而不是复用已看过的 MuSiQue 案例。

## 7. 结论边界

v73 不构成自动分解能力、官方 MuSiQue 答案或排行榜结果、FRC 检索效用、真实 SetR 复现、严格独立模型训练、洪水领域专家评测或生产放行证据。确认集、检索评分、选择器采用、CANARY 和 DEFAULT 均未授权，Gate 2 继续为 `NO-GO/SHADOW`。
