# SQuAD2 支持门迭代综合报告（v58—v61）

## 1. 研究目的

v58—v61 检验一个比“继续调整 FRC 选择器”更基础的问题：在答案存在、答案缺失各 300 条的均衡机制样本上，能否先用本地公开模型可靠判断候选上下文是否真正支持问题，再在完全相同的支持门内公平比较 FRC 与非 FRC 选择方法。

四轮均使用 SQuAD2 官方 `train-v2.0.json` 的互斥 600 条样本。v59 排除 v58 的 600 条承诺，v60 排除 v58—v59 的 1,200 条承诺，v61 排除 v58—v60 的 1,800 条承诺；各轮重叠均为 0。官方 `dev-v2.0.json` 仅按不透明字节下载和登记，未解析、未用于阈值或方法选择。

## 3. 可支持的结论

1. v59 的主要失败是输出协议而非理论选择规则：结构化输出使无效输出率由 50.33% 降至 1.67%。
2. v60 和 v61 中，候选 FRC 方法相对最强共享门非 FRC 基线的增益均显著为正；v61 也显著高于最强同门 FRC 消融。这说明在当前受控候选池和同一支持门内，FRC 的自适应选择逻辑具有稳定增量信号。
3. v61 仍未达到预注册的答案通过率 0.80、候选答案召回 0.75和平衡准确率 0.75。它距离平衡准确率门槛仅 0.001667，但答案召回仍低 0.095，因此不能以四舍五入或事后放宽门槛改判。
4. 支持判断是当前主要瓶颈。下一轮应优先更换为公开、任务匹配的抽取式 QA 支持模型，并在独立于其训练域的数据上检验迁移；不应继续用已揭示的 SQuAD2 train 个案调提示或门槛。

## 4. 严格边界

- 四轮都是均衡的机制实验，不是 SQuAD2 官方答案生成或排行榜结果。
- 本地 Qwen 是公开权重支持判断器，不是 SetR，也不构成真实 SetR 复现。
- `dev-v2.0.json` 未打开；四轮均在开发门失败后关闭，未启动确认评测。
- 选择器采用、CANARY、DEFAULT 与生产切流均未获授权；Gate 2 保持 `NO-GO/SHADOW`。
- 结果不等同于真实防汛语料、机构专家评审或生产安全验证。

## 5. 下一轮 v62 约束

v62 使用固定 revision 的 `deepset/roberta-base-squad2` 作为公开抽取式 QA 支持判断器。该模型在 SQuAD2 train 上训练，因此不得把本仓库的 SQuAD2 train 样本用于泛化主张。主开发评测改为 QuAC train 的新互斥样本，只有全部预注册门槛通过时才允许打开 QuAC validation；SQuAD2 dev 即使后续使用，也只能标注为组件可行性检查，不能冒充独立模型确认。
