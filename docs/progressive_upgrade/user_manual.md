# 区县防办响应闭环用户操作手册

## 正常流程

1. 管理员在“文档与规则版本”创建草稿，可输入文本或上传 TXT/Markdown、CSV、XLSX、DOCX、数字 PDF 或扫描图片。扫描件必须填写已核验 OCR 文本和 OCR 引擎版本；浏览器先计算 SHA-256，服务端再次校验。
2. 业务复核岗解析草稿，核对页码、章节、条款、表格行号、原文定位、解析器版本和解析哈希；解析失败时修正来源或 OCR 后重试，不得直接发布。
3. 业务复核岗或管理员发布解析成功的版本。已有当前版时必须明确替代旧版；发布后核对索引构建状态。重建失败不会覆盖最后一个成功索引，未生效、过期、替代、退役或失败版本不会进入检索。
4. 值班员确认页面顶部始终显示“受控模拟环境”，核对事件号、预警版本、来源和数据版本。
5. 在“待核验风险对象”运行筛查，查看排名及空间、时效、属性、语义、数据质量五类特征。无预警多边形时系统明确降级为区域台账模式；候选仍需人工确认。
6. 逐项确认或排除对象。预警更新后对象显示 `STALE`，必须重新筛查和核验，旧确认不能直接用于新草案。
7. 业务复核岗或授权审批岗点击“冻结确认清单”，核对清单版本、对象数和来源运行；对象变化时追加新版本，不覆盖旧版本。
8. 对最新冻结清单中的确认对象生成证据草案；系统自动绑定清单 ID、版本和哈希。证据工作台逐项显示触发条件、风险对象、责任主体、处置动作、完成时限、资源依赖、反馈要求、升级条件和例外条件的“有支持/有冲突/缺失”。缺失项必须显示原因，不能由模型常识补齐。
9. 展开来源卡片核对文档版本、条款、页码/表格行和原文定位；查看 NLI 状态和相邻证据包版本的字段、来源、冲突差异。如有冲突，复核或审批岗位选择合法来源并填写裁决理由；裁决产生新证据包版本。NLI 只提示候选，不替代人工判断文件效力。
10. 草案提交前查看规则校验。`HARD_BLOCK` 不可提交；`SOFT_WARNING` 需审批人员明确确认。任务同时绑定不可变的 Task Schema 与规则集版本。
11. 审批人员核对任务、对象、冻结清单、责任、四类时限、依据、证据包、执行合同和载荷哈希。高风险批准要求 AAL2 和理由。
12. 模拟下发写入 Outbox；“已送达”仅代表模拟接口接收，不代表真实跨部门接入。
13. 联络员确认接收并分派现场执行人。只有被分派执行人可以开始和反馈。
14. 执行人可以报告部分完成、资源不足、受阻或完成；部分完成保持任务可继续。
15. 延期由执行或联络岗位申请，由独立复核/审批岗位决定。
16. 通信或系统异常时，复核/审批岗位可人工接管；撤回任务仅授权审批岗位使用并要求理由。
17. 完成证据由独立人员核验；退回后继续执行，核验通过进入终态。
18. 全部必需任务完成、豁免或经授权撤回后，事件才可关闭并生成复盘草稿与场景报告。

## 故障处理

- `VERSION_CONFLICT`：刷新页面，比较新版本后重新编辑，不覆盖他人修改。
- `RULE_HARD_BLOCK`：按规则明细补证、处理冲突或修正字段，不可绕过。
- 候选清单版本冲突：刷新事件，重新核对最新预警、最新冻结版本和对象核验状态，不得选择历史版本继续成案。
- 文档 `parse_failed`：核对文件类型、SHA-256、OOXML/PDF 完整性或 OCR 核验状态后重试解析；不得把失败记录改成成功。
- 文档 `index_failed`：查看 IndexBuild 错误并重建；已发布版本保留最后成功索引，新草稿在索引成功前不得成为当前版。
- 文档版本冲突：发布新版本时明确指定当前版本为 `replace_version_id`，不得覆盖、删除或篡改旧版本。
- Outbox `failed`：检查审批载荷哈希，不允许把失败直接改成成功；转人工接管并对账。
- RAG/模型不可用：使用人工结构化草案和人工证据组装，确定性状态机继续运行。
- NLI 显示 `unavailable/partial/error`：保留确定性冲突规则和已发现冲突，不自动视为无冲突；必要时人工逐对核验并记录来源、结论和理由。
- 地图不可用：使用对象列表继续核验和处置。
- 身份或审计服务异常：失败关闭，不使用旧页面修改新版状态。
