# MuSiQue 多信号链支持门实验（v68）

## 1. 结论

v68 针对 v67 的“单一链瓶颈分数无法区分完整低置信链与真正断链”问题，预先冻结了九维数值特征和确定性约束逻辑回归。候选联合使用直接问题 margin、链内最小/平均 margin、高 margin 比例、相邻跳实体传递、所选段落差异、直接问题与末跳段落一致性及 hop 数指示；前七个证据信号系数强制非负。为避免把普通信号拼接误认为新机制，另设同一优化器、只使用直接 margin 和链最小 margin 的两信号控制。

1,200 条校准样本的五折完全 train-only 诊断中，多信号候选平衡准确率为 `0.691667`，高于两信号控制 `0.663333`、校准链瓶颈 `0.646667` 和校准直接问题 `0.611667`。但候选的答案通过率/无答案拒绝率为 `0.596667/0.786667`，没有同时达到冻结的 `0.60/0.80` 安全目标。协议规定校准只冻结参数，不产生采用结论，因此模型和阈值原样进入互斥开发集。

600 条开发样本上，多信号候选的答案通过率、无答案拒绝率和平衡准确率为 `0.573333/0.776667/0.675000`。最强公平基线是校准链瓶颈，指标为 `0.523333/0.753333/0.638333`。候选相对最强基线的同例正确性增益为 `+0.036667`，10,000 次 bootstrap 的 95% 区间为 `[+0.010000,+0.063333]`。这说明预注册多信号表示取得了稳定正增益，但未达到五个百分点实质门槛，也未达到平衡准确率、答案通过率和无答案拒绝率门槛。

开发状态冻结为：

`MUSIQUE_V68_MULTISIGNAL_CHAIN_DEVELOPMENT_SUPPORT_NOT_ESTABLISHED_STOP_BEFORE_CONFIRMATION`

确认阶段未打开。v68 校准或开发案例不得用于后验增加特征、改变模型、阈值、门槛或方法选择后再声称确认；选择器、检索评分、CANARY、DEFAULT 均未获授权，Gate 2 保持 `NO-GO/SHADOW`。

## 2. 冻结边界与样本隔离

- 数据为官方 MuSiQue revision `922ac98f19a201998dbdae6d7f2887a5258dbdeb`，许可 CC BY 4.0。
- 协议、来源登记、九个特征、模型、优化器、阈值规则、样本盐、门槛、实现和 13 项纯合成测试均在选择任何 v68 来源承诺前冻结。
- 校准与开发排除 v65 无效 300、v65 修正 600、v66 开发 600、v67 校准 1,000、v67 开发 600，共 3,100 个唯一历史来源承诺；开发另排除 v68 校准的 1,200 个承诺。
- 校准 1,200 个来源、开发 600 个来源均唯一，答案/无答案严格均衡；开发与校准、历史承诺及 SQuAD2 精确题面重叠均为 0。
- 校准的 2/3/4-hop 分布为 `887/258/55`，开发为 `443/122/35`。
- MuSiQue train/dev 文件此前已被仓库其他实验解析；v68 不声明首次访问或严格独立数据来源。
- 组合问题或任一分解问题与 SQuAD2 train 规范化题面精确相同的来源均被排除。该守卫不能排除释义、上下文或预训练重叠。

## 3. 方法

### 3.1 盲态完整链执行

1. 组合问题和每个分解问题都分别输入全部段落，并按最大有限 `null-vs-span` margin、段落顺序确定唯一结果；
2. 分解问题只提供文本和顺序，不提供分解答案、`paragraph_support_idx` 或 supporting 标记；
3. 后续 `#k` 只允许替换为固定 RoBERTa 模型前一跳预测的 span；
4. 中间 hop 不应用 margin 阈值，只在前驱不可解析或没有有限合法 span 时失败关闭；
5. 所有 QA 与九维特征完整写入后才连接 answerability 标签。

### 3.2 九维冻结特征

固定顺序为：

1. 直接问题 margin，经 `clip[-10,10]/10` 缩放；
2. 链内最小 margin，同样缩放；
3. 链内平均 margin，同样缩放；
4. hop margin 严格高于 v66 阈值 `0.974609375` 的比例；
5. 相邻 hop 中，至少三个字母数字字符的前一跳 span 出现在下一跳选中段落的比例；
6. 不同选中段落数除以 hop 数；
7. 直接问题与最后一跳选择同一段落的指示；
8. 3-hop 指示；
9. 4-hop 指示。

公共逐例证据只保存这些数值、决策哈希和 answerability，不保存问题、上下文、预测 span、来源 ID 或 gold supporting 字段。

### 3.3 确定性约束模型与公平对照

候选和两信号控制均使用零初始化、5,000 次全批投影梯度下降、学习率 `0.1`、L2 `0.01`。候选的前七个证据信号系数每步投影为非负；两个 hop 指示和截距不受符号约束。全部报告方法总计只从校准集学习 17 个标量：候选 11 个、两信号控制 4 个、直接和链瓶颈阈值各 1 个。

公平比较包括：

- 校准直接组合问题 margin；
- 固定 v66 阈值的完整链；
- 校准链瓶颈；
- 同优化器两信号逻辑回归；
- 九信号逻辑回归候选。

所有学习方法使用相同的严格 `score > threshold` 判定和阈值选择规则：优先同时满足答案通过率至少 0.60、无答案拒绝率至少 0.80，再最大化平衡准确率；若没有可行阈值，则最小化两项安全短缺。五折诊断在每个 held-out fold 上同时重学模型和阈值，禁止 held-out 标签进入训练。

## 4. 执行完整性

运行环境为 NVIDIA GeForce RTX 4060 Ti、Python 3.10.20、PyTorch 2.4.1+cu124、Transformers 4.46.3、FP16、batch size 16。

校准阶段：

- 直接组合问题：23,997 条段落 QA；
- hop 1：23,997 条；
- hop 2：23,997 条；
- hop 3：6,257 条；
- hop 4：1,100 条。

开发阶段：

- 直接组合问题：11,994 条段落 QA；
- hop 1：11,994 条；
- hop 2：11,994 条；
- hop 3：3,140 条；
- hop 4：700 条。

两阶段均无被阻断案例、无无效特征输出。校准和开发分别保存 1,200/600 条唯一压缩逐例证据；公共证据中没有原始问题、上下文、预测 span、来源 ID 或 supporting gold 字段。

- 2-hop：`0.761261`（222 例）；
- 3-hop：`0.807018`（57 例）；
- 4-hop：`0.857143`（21 例）。

- 平衡准确率 `0.675000 < 0.72`；
- 答案通过率 `0.573333 < 0.60`；
- 无答案拒绝率 `0.776667 < 0.80`；
- 相对最强公平基线 `+0.036667 < +0.05`。

## 6. 机制解释与下一步约束

v68 比 v67 更进一步：链内平均置信度、实体传递和段落覆盖等固定信号在全新开发集上带来了区间下界高于 0 的同例改进，因此“完整链不应只由最弱一跳决定”获得了前瞻性支持。但线性九信号表示仍没有形成同时满足召回和拒答安全线的可分区域；多信号候选提高答案通过率时，仍伴随不可回答误放。

下一轮若继续，必须永久排除 v68 的 1,800 个案例，并在选择新案例前冻结新的机制、实现和门槛。允许依据本报告的聚合结论提出新假设，例如测试预注册的非线性交互或显式链一致性状态；不得读取 v68 逐例证据来选择交互、切点、特征、正则强度或阈值，也不得把 v68 开发集重新命名为确认集。

## 7. 结论边界

v68 支持“预注册多信号链表示相对单一链瓶颈存在稳定正增益”，但不支持“该方法已达到安全、实质或可发布水平”。它不构成：

- 自动问题分解能力证明；
- 官方 MuSiQue 答案生成或排行榜结果；
- FRC-RAG 与检索基线的效用比较；
- 真实 SetR 复现；
- 严格独立模型训练、洪水领域专家或生产放行证据。

确认集、检索评分和选择器采用均未授权，Gate 2 继续为 `NO-GO/SHADOW`。
