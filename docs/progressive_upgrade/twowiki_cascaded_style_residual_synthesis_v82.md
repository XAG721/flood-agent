# 2Wiki 题型级联与安全残差路由前瞻开发实验综合报告（v82）

## 结论

v82 针对 v81 的两个明确缺口进行受控改进：一是 comparison 相对题型最佳 cross-encoder 对照退化，二是总体增益未达到 `+0.005`。新路由器先用问题文本识别直接 comparison 并固定走 cross，其余样本不再允许 cross 残差覆盖，只允许 v81 预测的软/锚翻转在其增益同时超过 cross 增益和冻结阈值时覆盖 v75 默认路线。

在新的800条案例互斥 2WikiMultiHopQA 开发样本上，候选证据宏 F1 为 `0.544792`，v75 为 `0.538284`，v81 为 `0.542649`。候选相对 v75 为 `+0.006508`，95% CI `[+0.003373,+0.009762]`；相对本批最强登记对照 v81 为 `+0.002143`，95% CI `[+0.000357,+0.004286]`。候选修复了 v81 的 comparison 分层失败，且相对 v81 的区间为正，但没有达到预注册的至少 `+0.005` 实际优势线。

最终状态为：

`2WIKI_V82_CASCADED_ROUTER_DEVELOPMENT_ADVANTAGE_NOT_ESTABLISHED_STOP`

16项严格门槛中只有“相对最强登记对照至少 `+0.005`”失败，全部非劣条件通过。因此确认阶段没有打开，也没有选择任何确认 ID。选择器、CANARY、DEFAULT 和 Gate 2 均未获授权，Gate 2 保持 `NO-GO/SHADOW`。

## 模型开发

v82 把以下三个已经揭示且永久排除的批次登记为训练/诊断数据：

| 训练批次 | 案例数 | v82 样本外子模型预测方式 |
| --- | ---: | --- |
| v75 开发 | 800 | v81 五折中对应的 held-out 折模型 |
| v75 确认 | 800 | v81 五折中对应的 held-out 折模型 |
| v81 开发 | 800 | 未见过该批次的 v81 完整模型 |
| 合计 | 2400 | 每例均使用样本外 v81 增益预测 |

直接 comparison 分类器只以历史官方题型作为训练标签，运行时输入仅为问题文本。有限搜索包含4个哈希维度、4个 L2、5个直接 comparison 阈值和7个安全翻转阈值，共 `560` 个策略。安全候选必须同时满足逐题型相对 v75 不低于 `-0.005`、三个训练批次均不退化、直接 comparison 平衡准确率不低于 `0.90`、覆盖率和默认动作占比约束。

最终冻结配置为：

- 哈希维度：`256`
- L2：`32.0`
- 直接 comparison 阈值：`0.8`
- 安全翻转阈值：`0.015`
- 动作优先级：直接 comparison → cross；否则安全翻转；否则 v75 默认

五折样本外模型选择诊断中，候选 F1 为 `0.543817`，v75 为 `0.537084`，差值 `+0.006733`，95% CI `[+0.005079,+0.008505]`。v75 开发、v75 确认和 v81 开发三个训练批次的差值分别为 `+0.007183/+0.006151/+0.006865`。这些结果参与配置选择，只是开发证据，不是独立确认。

## 冻结与盲化

任何 v82 目标 ID 选择前，路由模块、传输模块、两个运行脚本、两组专项测试、协议、源登记和模型产物共9个文件均已按字节数与 SHA-256 锁定。冻结前9项测试、冻结后10项包含 v81/v82 锁检查的测试均通过。

目标源仍为 2WikiMultiHopQA `dev.parquet`。v82 永久排除以下4200个两两互斥的既往 ID：

| 排除来源 | 案例数 |
| --- | ---: |
| 早期公共参考池 | 1000 |
| v74 开发 | 800 |
| v75 开发 | 800 |
| v75 确认 | 800 |
| v81 开发 | 800 |
| 合计 | 4200 |

开发集在锁后按冻结盐值选择，四题型各200例，与全部既往 ID 重叠为0，共含25305个候选段落。盲文件不含答案、gold ID、gold 标志或 gold 角色。冻结 BGE embedding/reranker 在 GPU 上完成 `800/800` 条评分，耗时 `1132.895205` 秒；评分文件在 gold 联结前落盘，SHA-256 为 `ff45c917da1941f295316061bbae41ce84d461223756db0a3857cd462adbe1fe`。

逐题型相对各自最佳登记对照的差值为：

## 停止规则与后续边界

v82 开发严格门失败后，确认集保持关闭；不得把未打开的确认阶段伪造为已完成，也不得修改 v82 阈值或门槛后继续使用同一开发集声称通过。该800条开发样本从现在起只能作为未来版本的训练/诊断历史。

若继续 v83，必须：

1. 登记新实验版本，并把 v82 开发集加入永久排除，使既往 2Wiki 暴露总数达到5000；
2. 在任何新目标 ID 选择前冻结模型、控制、门槛和停止规则；
3. 把相对 v81 的增量作为直接设计目标，而不是只重复证明相对 v75 的优势；
4. 只从剩余未触碰样本中选择新开发/确认样本，不得回用 v82 开发集；
5. 继续保持真实 SetR、答案生成、洪水专家、CANARY、DEFAULT 和生产结论的边界。

本轮不是独立数据集、官方 2Wiki 排行榜、答案生成质量、真实 SetR、洪水领域专家或生产证据。完整机器证据位于协议、源登记、实现锁、模型开发、执行、结果、关闭记录以及 `output/rag_evaluation/twowiki_cascaded_router_v82/development/`。
