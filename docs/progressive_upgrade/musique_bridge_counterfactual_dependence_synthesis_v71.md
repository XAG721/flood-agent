# MuSiQue 桥接实体反事实依赖支持门实验（v71）

## 1. 结论

v71 检验一个预先冻结的机制假设：如果多跳答案确实依赖中间桥接实体，那么把下游分解问题中的每个 `#k` 桥接占位符替换为固定哨兵 `unknown bridge entity`，应降低段落支持 margin、改变获胜段落或改变归一化预测 span。

开发集上，15 特征候选的答案通过率、无答案拒绝率和平衡准确率分别为 `0.622500/0.790000/0.706250`。最强公平基线和最强既有特征控制均为 v69 的单调加性分段控制，指标为 `0.620000/0.825000/0.722500`。候选相对它的同例正确性差值为 `-0.016250`：公平基线 10,000 次 bootstrap 的 95% 区间为 `[-0.033750,+0.002500]`，独立既有特征控制区间为 `[-0.035000,+0.002500]`。

候选相对六特征反事实信号单独控制提高 `+0.091250`，95% 区间为 `[+0.056250,+0.126250]`。这说明九个既有基础特征携带重要信息，但不能证明六个桥接反事实特征在既有特征之上提供增量。候选还未达到 `0.72` 平衡准确率和 `0.80` 无答案拒绝率门槛。因此 v71 的预注册机制支持未建立，状态冻结为：

`MUSIQUE_V71_BRIDGE_COUNTERFACTUAL_DEVELOPMENT_SUPPORT_NOT_ESTABLISHED_STOP_BEFORE_CONFIRMATION`

确认集不打开，选择器和检索评分不采用该方法，CANARY 与 DEFAULT 均未授权，Gate 2 保持 `NO-GO/SHADOW`。

## 2. 冻结边界与隔离

- 数据为官方 MuSiQue revision `922ac98f19a201998dbdae6d7f2887a5258dbdeb`，许可证为 CC BY 4.0。
- v71 只使用 v70 聚合结论提出不同机制，没有读取 v70 个案预测、错误、特征或分组来选择 v71 特征、模型、优化器或门槛。
- 协议、六个反事实特征、118 个学习标量、对照组、阈值规则、bootstrap 种子及全部门槛均在选择任何 v71 样本前冻结。
- 永久排除 v65–v70 共 9,700 个唯一历史来源承诺；开发集再排除 1,600 个 v71 校准来源承诺。
- 校准集为 800 条可回答和 800 条不可回答样本，开发集为 400/400；与历史/校准来源及 SQuAD2 规范化精确题面重叠均为 0。
- 校准集 2/3/4-hop 分布为 `1202/334/64`，开发集为 `590/166/44`。
- 官方分解仅提供问题模板与顺序。链的桥接实体来自冻结 QA 模型的上游预测，不使用分解答案、`paragraph_support_idx` 或 supporting 标记。因此这仍是 oracle 计划组件实验，不是自动分解结果。

## 3. 方法与公平控制

在事实链完整运行后，每个下游问题使用相同 20 个候选段落进行一次反事实 QA。每个 `#k` 被机械替换为固定哨兵；若官方模板没有占位符，则执行零次替换，问题保持不变。同一确定性模型在相同段落上应产生零依赖。

每个事实/反事实转换计算三种变化：正向 margin 降幅、获胜段落是否变化、归一化 span 是否变化。六个新特征依次为三种变化在链上的最小值和均值：

1. `bridge_margin_drop_min`
2. `bridge_margin_drop_mean`
3. `bridge_paragraph_change_min`
4. `bridge_paragraph_change_mean`
5. `bridge_span_change_min`
6. `bridge_span_change_mean`

候选由 v68 的九个基础特征加六个新特征组成，共 15 维；13 个非 hop 指示特征的系数投影为非负。公平比较包括校准直接问题、固定 v66 完整链、校准链瓶颈，以及在同一 v71 校准数据和同一优化器上拟合的九信号线性控制、v69 27 特征加性控制、v69 32 特征交互控制、v70 15 特征段落竞争控制和六特征反事实信号单独控制。全部报告方法合计只从校准集学习 118 个标量。

## 4. 实现勘误

首次执行校准 QA 时，事实直接问题和事实链全部完成，但实现错误地要求每个下游官方分解问题至少包含一个 `#k`。在 2,062 个下游转换中有 58 个模板没有占位符，因此程序在创建任何反事实输入、读取反事实输出、生成特征决策、拼接金标或计算指标之前停止。

正式勘误把空占位符集合解释为零次替换，并在反事实输入中记录 `placeholder_substitutions`。修正后 16/16 项合成测试通过。协议、样本、特征、模型、优化器、阈值、门槛、阶段规模和 118 个学习标量均未改变；原始及修正后哈希链和精确失败边界保存在 `musique_bridge_counterfactual_dependence_implementation_erratum_v71.json`。

## 6. 解释与后续约束

固定哨兵反事实变化本身携带一定可回答性信息，但在九个基础特征上加入它没有提高开发集性能。特别是五个新特征在校准中被非负投影压到零，剩余特征的权重也很小，说明当前替换方式没有提供稳定的新增判别信息。

这只否定本次预注册的“固定英文哨兵 + margin/段落/span 变化最小值与均值 + 单调线性组合”，不能推断所有桥接反事实方法无效。可能的机制问题包括：无占位符模板天然产生零信号、固定英文哨兵形成分布外问题，以及抽取式 QA 对实体替换不够敏感。但 v71 的 2,400 个校准/开发案例不得用于筛选新哨兵、掩码、扰动、统计量、模型、阈值或门槛后再声称确认。

若继续研究，必须提出不同且可证伪的机制，永久排除 v65–v71 已用来源，并在选择任何新样本前重新冻结实现和公平对照。

## 7. 结论边界

v71 不构成自动分解能力、官方 MuSiQue 答案或排行榜结果、FRC 检索效用、真实 SetR 复现、严格独立模型训练、洪水领域专家评测或生产放行证据。确认集、检索评分、选择器采用、CANARY 和 DEFAULT 均未授权，Gate 2 继续为 `NO-GO/SHADOW`。
