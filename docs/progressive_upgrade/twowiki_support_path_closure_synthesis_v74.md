# 2WikiMultiHopQA 标题链接支持路径闭包实验（v74）

## 1. 结论

v74 把 v65–v73 已耗尽的 MuSiQue 迭代链切换到新的公开来源，并把此前已公开过结果的 1,000 个 2WikiMultiHopQA ID 明确登记为机制开发历史集、永久排除。真正的开发集从剩余 ID 中按冻结 SHA-256 顺序抽取 800 例，`bridge_comparison/comparison/compositional/inference` 各 200 例，与历史集重叠为 0。

候选 `soft_title_link_support_path_closure_v74` 在冻结 BGE/Reranker 分数上以精确标题链接构造无 gold 支持图，选择分数固定为：

`cross_encoder + 1.0 × linked_to_any_selected + 0.1 × source_not_yet_selected`

开发集证据 F1、证据召回、完整证据召回分别为 `0.518988/0.809375/0.607500`。相对现有 `frc_select` 的 F1 增益为 `+0.076095`，10,000 次同例 bootstrap 的 95% 区间为 `[+0.063476,+0.088913]`；这表明标题链接路径闭包显著改善了当前静态 FRC 选择器在该受控多跳证据任务上的检索结果。

但最强公平对照不是现有 FRC，而是冻结的 `alternating_anchor_link_control`，其 F1 为 `0.517270`。候选相对它仅提高 `+0.001718`，95% 区间为 `[-0.008036,+0.011401]`，未达到预注册的 `+0.01` 且区间下界不高于 0。候选还在 `bridge_comparison` 与 `comparison` 两个类型上分别低于最强对照 `-0.044556/-0.044286`，违反每个类型至少 `-0.02` 的安全门槛。

因此 v74 支持路径闭包相对旧 FRC 的改进成立，但“软闭包优于最强同资源图对照”的增量机制支持未建立。状态冻结为：

`2WIKI_V74_SUPPORT_PATH_CLOSURE_DEVELOPMENT_SUPPORT_NOT_ESTABLISHED_STOP_BEFORE_CONFIRMATION`

确认集不打开，开发案例不得用于现场修改规则后声称确认；选择器、CANARY、DEFAULT 均未授权，Gate 2 保持 `NO-GO/SHADOW`。

## 2. 预注册与盲化边界

- 官方开发文件固定为 `30,056,098` 字节，SHA-256 为 `c0d8b60b9026b728fb07ad74c5252a0f188f6942e8ba5c02df4dfa369502ea8d`，共 12,576 行。
- 历史机制集候选池与冻结分数分别固定为 `3398c12e...b8a2` 与 `7add5a5e...6104`，其中 1,000 个 ID 永久排除。
- 协议在读取任何新目标行前冻结；实现锁定时 v74 目标行、开发 ID、模型输出和 gold 指标读取数均为 0。
- 模型侧盲化文件不含答案、gold evidence ID、gold 标志或 gold role。
- 800 例模型分数全部写完并固定哈希后，先生成 11 个方法的 selection output，再进行 sealed gold join。
- 选择器不读取官方问题类型；问题类型只用于预注册均衡抽样和事后分层安全检查。

## 3. 历史机制开发与公平对照

历史集上有限搜索空间包含 `7 × 3 = 21` 个软链接/来源多样性组合和 3 个可解释图控制，共 24 个配置。选定候选在历史集上的 F1 为 `0.516325`，相对交叉编码器/FRC 的 `0.443618` 提高 `+0.072707`。这些结果仅用于冻结 v74，相关 1,000 个 ID 未进入目标开发集。

开发阶段所有方法严格共用：

- `BAAI/bge-large-en-v1.5@d4aa6901...`；
- `BAAI/bge-reranker-large@55611d7b...`；
- 每例 min-max 分数、`role_relevance_mix=0.15`、`rrf_k=60`；
- `top_k=5` 与 `token_budget=1500`；
- 相同的 800 个案例和 24,354 个候选句。

十个对照覆盖 BM25、dense、hybrid、cross encoder、coverage greedy、现有 FRC、图结构单独控制、无来源多样性软链接、硬链接链和交替锚点链接。因此最强基线不是名称性基线，而是同数据、同模型、同预算下开发集实际最强的冻结对照。

## 5. 解释与下一步约束

结果把两个问题分开了：

1. **标题链接图是否值得加入现有 FRC？** 是。在同模型、同预算下，候选相对现有 FRC 的 F1 提高 7.61 个百分点，完整证据召回提高 21.75 个百分点。
2. **软闭包评分是否优于更简单的交替锚点链接？** 尚无证据。两者总体 F1 几乎相同，区间覆盖负增益。

分层结果显示，软闭包对 `compositional/inference` 分别提高 `+0.037143/+0.058571`，但对两类 comparison 问题约退化 4.4 个百分点。这支持一个新的、可证伪的研究方向：使用运行时可观察的问题表述或检索图形态，在“链式闭包”与“交替锚点”之间做预注册路由。不过 v74 的 800 个开发案例和任何派生错误分组都不得再作为未来确认集；若研究路由，必须登记为新的机制开发历史，并在新的互斥公共来源或此前未读取的 ID 上冻结验证。
