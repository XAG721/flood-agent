# AgentTwin Flood 街道级智能体数据需求清单

## 1. 文档目的

本文档面向更小范围的落地场景：**一个街道或办事处辖区**。

相比县级或全域防汛系统，街道级智能体不需要一开始就覆盖完整水库、流域、尾矿库、南水北调等复杂工程体系。它更适合先围绕以下目标建设：

- 接收上级预警和本地雨情积水信息。
- 汇总群众反馈和网格员上报。
- 识别辖区内重点对象和重点人群。
- 给出巡查、转移、排涝、通知、上报等建议。
- 跟踪任务是否有人接收、是否完成、是否需要升级。

街道级智能体的核心价值是：**帮助街道值班人员在信息很多、人手有限的情况下，快速看清哪里最急、谁最需要帮助、该通知谁、该派谁去、哪些情况要向上级报告。**

## 2. 街道级数据范围总览

| 数据类别 | 是否建议街道级必备 | 说明 |
|---|---|---|
| 街道指挥与责任人数据 | 必备 | 明确街道、社区、网格责任人和联系方式 |
| 预警与响应规则数据 | 必备 | 以上级预警和街道处置SOP为主 |
| 本地雨情、积水与洪水预测结果 | 必备 | 可接入简化预测、上级研判或积水风险图 |
| 重点对象画像数据 | 必备 | 学校、医院、养老院、地下空间、低洼小区等 |
| 重点人群数据 | 必备 | 独居老人、残疾人、低洼区住户等 |
| 群众反馈与网格员上报数据 | 必备 | 街道级智能体最关键的信息来源 |
| 街道可用队伍、物资与装备数据 | 必备 | 以小型排涝、巡查、转移、通知资源为主 |
| 避险转移与临时安置数据 | 必备 | 社区临时安置点、转移路线、接驳方式 |
| 信息上报与通知发布数据 | 必备 | 向区县上报、向社区和群众通知 |
| 交通道路与通行状态 | 建议必备 | 重点关注低洼路段、下穿通道、学校医院周边 |
| 生命线设施状态 | 建议接入 | 重点关注断电、断网、供水异常对重点对象影响 |
| 特殊设施状态 | 按需接入 | 街道内有医院、学校、养老院、危化点时接入 |
| 潜在额外可用数据 | 可选 | 视频、无人机、舆情、微信群文本等 |

## 3. 街道指挥与责任人数据

### 3.1 数据内容

街道级不需要复杂的多级指挥体系，但必须知道街道、社区、网格和重点对象责任人。

### 3.2 建议采集内容

- 街道防汛负责人。
- 街道值班人员。
- 各社区负责人。
- 各网格员。
- 重点对象联系人，如学校负责人、医院值班负责人、养老院负责人、物业负责人。
- 街道可联系的上级防指、应急、水务、城管、公安、消防、卫健、民政联系人。

### 3.3 最小字段

| 字段名称 | 字段解释 |
|---|---|
| `person_id` | 责任人ID。 |
| `name` | 姓名。 |
| `role` | 角色，如街道值班员、社区书记、网格员、物业负责人。 |
| `area_or_grid` | 负责社区、网格或对象。 |
| `phone` | 联系电话。 |
| `backup_phone` | 备用电话。 |
| `duty_status` | 当前是否值班或可联系。 |
| `responsible_object_ids` | 负责的重点对象ID。 |
| `updated_at` | 更新时间。 |

### 3.4 智能体用途

- 自动生成叫应名单。
- 将群众反馈分派给对应网格员。
- 判断某个重点对象应该通知谁。
- 发现责任人未反馈时提醒升级。

## 4. 预警与响应规则数据

### 4.1 数据内容

街道级规则应以“简单、可执行”为主，不必复制完整县级预案。

### 4.2 建议采集内容

- 上级发布的暴雨、洪水、内涝预警等级。
- 街道内部值守加强规则。
- 社区和网格员巡查规则。
- 低洼小区、地下空间、学校、养老院、危旧房的通知和转移规则。
- 向上级报告的触发条件。
- 群众通知模板。

### 4.3 最小字段

| 字段名称 | 字段解释 |
|---|---|
| `rule_id` | 规则ID。 |
| `rule_name` | 规则名称。 |
| `trigger_condition` | 触发条件，如暴雨橙色预警、积水超过30厘米、群众集中报险。 |
| `street_action` | 街道需要执行的动作。 |
| `community_action` | 社区需要执行的动作。 |
| `grid_action` | 网格员需要执行的动作。 |
| `report_to_upper_required` | 是否需要上报区县。 |
| `public_notice_required` | 是否需要通知群众。 |
| `approval_required` | 是否需要街道领导或上级确认。 |
| `source` | 来源，如街道SOP、上级预案、工作手册。 |

### 4.4 智能体用途

- 根据上级预警自动生成街道处置清单。
- 提醒网格员巡查哪些点。
- 判断是否需要向上级报送。
- 检查通知内容是否符合规则。

## 5. 本地雨情、积水与洪水预测结果

### 5.1 数据内容

街道通常不直接运行复杂洪水模型，但可以使用更轻量的数据：

- 上级气象、水务、应急部门推送的预测结果。
- 简化积水风险图。
- 历史易涝点风险等级。
- 模型预测截图、PDF、会商纪要。
- 网格员现场水深估计。
- 视频识别积水结果。

### 5.2 建议采集内容

结构化数据：

- 当前雨量。
- 未来1小时、3小时降雨预报。
- 当前积水点水深。
- 预测积水范围。
- 预计影响时间。
- 预计退水时间。
- 受影响道路和重点对象。
- 预测置信度。

非结构化数据：

- 上级部门预测报告。
- 水务或气象会商纪要。
- 淹没风险图。
- 模型输出截图。
- 网格员拍摄的积水照片和视频。

### 5.3 最小字段

| 字段名称 | 字段解释 |
|---|---|
| `prediction_id` | 预测结果ID。 |
| `source` | 来源，如上级防指、水务、气象、模型、人工会商。 |
| `valid_time_window` | 预测有效时间范围。 |
| `affected_area` | 预测影响区域。 |
| `predicted_water_depth` | 预测积水深度，可为空或区间值。 |
| `predicted_arrival_time` | 预计影响到达时间。 |
| `predicted_recession_time` | 预计退水时间。 |
| `affected_roads` | 预计受影响道路。 |
| `affected_object_ids` | 预计受影响重点对象ID。 |
| `confidence` | 置信度或可信程度。 |
| `raw_material_url` | 原始报告、图片、PDF或截图链接。 |
| `updated_at` | 更新时间。 |

### 5.4 智能体用途

- 提前判断哪些社区、道路、学校、养老院会受影响。
- 计算处置窗口。
- 建议提前通知、巡查或转移。
- 将非结构化预测报告转成街道可执行任务。

## 6. 重点对象画像数据

### 6.1 街道级重点对象范围

街道级建议优先维护以下对象：

- 低洼小区。
- 地下车库和地下商场。
- 学校、幼儿园。
- 社区卫生服务中心、医院、诊所。
- 养老院、日间照料中心。
- 危旧房。
- 下穿通道、低洼路段。
- 社区避险点。
- 变电室、通信机房、水泵房。
- 有危化品、小型仓储或燃气风险的点位。

### 6.2 最小字段

| 字段名称 | 字段解释 |
|---|---|
| `object_id` | 重点对象ID。 |
| `object_name` | 对象名称。 |
| `object_type` | 对象类型。 |
| `community` | 所属社区。 |
| `grid_id` | 所属网格。 |
| `address` | 地址。 |
| `location_hint` | 现场定位说明。 |
| `longitude` | 经度。 |
| `latitude` | 纬度。 |
| `risk_tags` | 风险标签，如低洼、地下空间、老人多、儿童多。 |
| `current_population_estimate` | 当前估计人数。 |
| `responsible_person_id` | 责任人ID。 |
| `emergency_contact_phone` | 应急联系电话。 |
| `nearest_shelter` | 最近避险点。 |
| `evacuation_route` | 推荐转移路线。 |
| `last_inspected_at` | 最近巡查时间。 |
| `current_status` | 当前状态，如正常、预警、需巡查、需转移、已处置。 |

### 6.3 智能体用途

- 根据雨情和预测结果筛选重点对象。
- 对每个对象生成风险说明。
- 推荐巡查、通知、转移或资源前置。

## 7. 个体与重点人群数据

### 7.1 数据内容

街道级重点是掌握辖区内需要优先保护的人。

### 7.2 建议采集内容

- 独居老人。
- 残疾人。
- 卧床或行动不便人员。
- 孕妇。
- 慢性病患者。
- 留守儿童。
- 住在低洼院落、一楼、地下室、危旧房的住户。

### 7.3 最小字段

| 字段名称 | 字段解释 |
|---|---|
| `person_case_id` | 脱敏人员ID。 |
| `community` | 所属社区。 |
| `grid_id` | 所属网格。 |
| `location_hint` | 位置描述，可按权限脱敏。 |
| `person_type` | 重点人群类型。 |
| `risk_tags` | 风险标签。 |
| `mobility_need` | 转移需求，如步行、轮椅、担架、车辆。 |
| `medical_need` | 医疗需求，如吸氧、定时用药、透析。 |
| `responsible_grid_worker_id` | 负责网格员ID。 |
| `emergency_contact` | 紧急联系人，可按权限隐藏。 |
| `last_contact_status` | 最近联系状态。 |
| `transfer_status` | 转移状态。 |
| `updated_at` | 更新时间。 |

### 7.4 智能体用途

- 生成优先联系和上门确认名单。
- 计算转移所需车辆、轮椅、担架、医护陪同。
- 跟踪是否联系成功、是否已转移。

## 8. 群众反馈与网格员上报数据

### 8.1 数据内容

这是街道级智能体最关键的数据来源之一。

### 8.2 建议采集内容

- 群众电话、12345、小程序、微信群、短信、App报险。
- 网格员文字、语音、图片、视频、定位上报。
- 物业、学校、医院、养老院、社区工作人员反馈。

### 8.3 最小字段

| 字段名称 | 字段解释 |
|---|---|
| `report_id` | 上报ID。 |
| `report_source` | 来源，如群众、网格员、物业、学校、医院。 |
| `channel` | 渠道，如电话、小程序、微信群、App。 |
| `raw_content` | 原始内容。 |
| `media_urls` | 图片、视频、音频链接。 |
| `location_hint` | 上报位置描述。 |
| `gps_location` | GPS位置。 |
| `incident_type` | 事件类型，如积水、倒灌、人员被困、道路阻断。 |
| `urgency_level` | 紧急程度。 |
| `linked_object_id` | 关联重点对象ID。 |
| `verification_status` | 核实状态。 |
| `handling_status` | 处理状态。 |
| `assigned_person_id` | 分派处理人ID。 |
| `reported_at` | 上报时间。 |

### 8.4 智能体用途

- 自动分类、去重、聚类。
- 判断哪些反馈最紧急。
- 推荐派给哪个网格员或社区。
- 将非结构化反馈转为任务。

## 9. 街道可用队伍、物资与装备数据

### 9.1 数据内容

街道级资源通常不大，但很关键。

### 9.2 建议采集内容

- 街道应急队伍。
- 社区志愿者。
- 网格员。
- 物业人员。
- 小型抽水泵。
- 沙袋、挡水板。
- 雨衣、手电、扩音器。
- 应急车辆。
- 对讲机或卫星电话。

### 9.3 最小字段

| 字段名称 | 字段解释 |
|---|---|
| `resource_id` | 资源ID。 |
| `resource_type` | 资源类型。 |
| `resource_name` | 资源名称。 |
| `quantity_total` | 总数量。 |
| `quantity_available` | 可用数量。 |
| `location` | 存放或当前位置。 |
| `responsible_person_id` | 负责人ID。 |
| `status` | 状态，如可用、已派出、损坏、不可用。 |
| `task_capability` | 可支持任务，如排水、巡查、转移、通知。 |
| `updated_at` | 更新时间。 |

### 9.4 智能体用途

- 判断是否能执行排水、巡查、转移。
- 推荐最近可用资源。
- 提醒资源不足并建议向上级申请支援。

## 10. 避险转移与临时安置数据

### 10.1 数据内容

街道级重点是掌握辖区内临时避险点和短距离转移路线。

### 10.2 建议采集内容

- 社区党群服务中心。
- 学校体育馆。
- 街道办事处。
- 临时安置房间。
- 高地或安全集合点。
- 转移路线。
- 接驳车辆。

### 10.4 智能体用途

- 推荐重点人群转移目的地。
- 判断安置点是否适合老人、病患、儿童。
- 生成转移批次和路线建议。

## 12. 特殊设施运行状态数据

街道级只需要维护辖区内实际存在的特殊设施。

- 学校和幼儿园。
- 社区医院、卫生服务中心、诊所。
- 养老院、日间照料中心。
- 地下商场、地下车库。

### 12.3 智能体用途

- 生成对象专属处置建议。

| `operational_status` | 运行状态。 |
| `failure_cause` | 故障原因。 |
| `critical_users_affected` | 受影响重点对象。 |
| `estimated_recovery_time` | 预计恢复时间。 |
| `responsible_unit` | 责任单位。 |
| `contact_person` | 联系人。 |
| `updated_at` | 更新时间。 |

### 14.3 智能体用途

- 判断重点对象是否失去基础保障。
- 提醒上级和相关企业抢修。
- 调整安置点和转移建议。

## 15. 潜在额外可用数据

### 15.1 街道级可选数据

- 视频监控截图或AI识别结果。
- 无人机巡查影像。
- 小区微信群、物业群、社区群文本。
- 舆情或群众集中投诉信息。
- 导航拥堵数据。
- 手机人流热力。
- 物业巡查记录。
- 历史易涝点照片。

### 15.2 智能体用途

- 辅助核验群众反馈。
- 发现还没有进入正式系统的风险。
- 判断公众关注和恐慌情绪。
- 提供会商证据。

## 16. 街道级最小落地建议

如果只做一个街道范围，建议先准备以下最小数据包：

1. 街道、社区、网格责任人通讯录。
2. 低洼点、地下空间、下穿通道、危旧房、学校、养老院、医院等重点对象清单。
3. 重点人群脱敏台账。
4. 群众反馈和网格员上报入口。
5. 简化雨情、积水、预测结果或上级研判信息。
6. 街道可用物资和队伍清单。
7. 临时避险点和转移路线。
8. 上报模板和群众通知模板。

这 8 类数据具备后，智能体就可以先实现街道级核心能力：

```text
接收预警 -> 汇总上报 -> 识别重点对象 -> 判断重点人群
-> 生成巡查和转移建议 -> 通知责任人 -> 跟踪任务 -> 上报结果
```
