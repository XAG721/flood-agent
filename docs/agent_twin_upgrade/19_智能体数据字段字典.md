# AgentTwin Flood 智能体数据字段字典

## 1. 文档目的

本文档用于整理智能体真实落地所需的数据字段。与上一份“数据需求清单”不同，本文档更偏向字段字典，只保留以下 12 类数据：

1. 指挥机构数据
2. 预警与响应规则数据
3. 重点对象画像数据
4. 个体与重点人群数据
5. 队伍、物资与装备数据
6. 避险转移与安置数据
7. 信息报送与发布数据
8. 特殊设施运行状态数据
9. 特殊设施信息
10. 交通枢纽和道路运行状态
11. 电力、通信、供水、供气等生命线设施状态
12. 潜在的额外可用数据

字段命名采用英文 `snake_case`，便于后续转成数据库字段、接口字段或前端类型。

## 2. 指挥机构数据

用于让智能体知道防汛体系中“谁负责、谁指挥、谁审批、谁执行”。

| 字段名称 | 字段解释 |
|---|---|
| `command_org_id` | 指挥机构唯一ID，如县防指、乡镇防指、专项工作组。 |
| `org_name` | 指挥机构名称。 |
| `org_level` | 机构层级，如县级、乡镇级、村社区级、专项组。 |
| `parent_org_id` | 上级指挥机构ID，用于形成组织层级关系。 |
| `jurisdiction_area_id` | 机构负责的行政区域或网格区域ID。 |
| `jurisdiction_area_name` | 机构负责区域名称。 |
| `duty_scope` | 机构职责范围，如会商调度、城市内涝、山洪防御、物资保障。 |
| `activation_condition` | 机构进入工作状态或集中办公的触发条件。 |
| `office_location` | 指挥机构办公地点或应急值守地点。 |
| `primary_contact_person_id` | 主要负责人或值班负责人ID。 |
| `backup_contact_person_id` | 备用负责人ID。 |
| `contact_phone` | 联系电话。 |
| `contact_channels` | 可用联系渠道，如电话、短信、政务平台、工作群。 |
| `duty_shift` | 当前值班班次信息。 |
| `on_duty_status` | 当前值守状态，如正常值守、加强值守、集中办公、前方指挥。 |
| `available_decision_authority` | 当前机构可做出的决策范围，如启动响应、发布预警、调度资源。 |
| `last_confirmed_at` | 最近一次值守或联络确认时间。 |
| `data_source` | 数据来源，如通讯录、值班系统、组织机构库。 |
| `updated_at` | 数据更新时间。 |

## 3. 预警与响应规则数据

用于让智能体根据雨情、水情、险情、灾情判断是否需要预警、叫应、启动响应或调整响应等级。

| 字段名称 | 字段解释 |
|---|---|
| `rule_id` | 规则唯一ID。 |
| `rule_name` | 规则名称，如暴雨橙色预警响应规则、山洪立即转移规则。 |
| `hazard_type` | 灾害类型，如暴雨、洪水、山洪、地质灾害、城市内涝。 |
| `warning_level` | 预警等级，如蓝色、黄色、橙色、红色。 |
| `response_level` | 应急响应等级，如四级、三级、二级、一级。 |
| `trigger_condition_text` | 规则触发条件的文字描述。 |
| `metric_thresholds_json` | 结构化阈值，如雨量、水位、积水面积、受灾人数等。 |
| `affected_area_condition` | 影响区域条件，如多个乡镇受影响、城区大面积积水。 |
| `risk_object_condition` | 重点对象触发条件，如学校、医院、养老院、地下空间受威胁。 |
| `required_consultation_units` | 触发后必须参与会商的单位列表。 |
| `required_actions` | 触发后必须执行的动作，如会商、叫应、转移、巡查、报送。 |
| `optional_actions` | 建议执行但非强制的动作。 |
| `call_required` | 是否需要叫应责任人。 |
| `call_targets` | 需要叫应的对象，如县级责任人、乡镇责任人、村级责任人。 |
| `approval_required` | 是否需要人工审批或领导签发。 |
| `approval_role_required` | 需要审批的角色，如指挥长、值班领导、行业主管部门。 |
| `reporting_required` | 是否需要信息报送。 |
| `reporting_deadline_minutes` | 报送时限，单位分钟。 |
| `reporting_frequency` | 续报频率，如每30分钟、每1小时。 |
| `public_warning_required` | 是否需要对公众发布预警或提示。 |
| `termination_conditions` | 响应调整或结束条件。 |
| `source_plan_id` | 来源预案ID。 |
| `source_clause` | 来源条款编号或章节位置。 |
| `valid_from` | 规则生效时间。 |
| `valid_until` | 规则失效时间。 |
| `updated_at` | 规则更新时间。 |

## 4. 重点对象画像数据

用于让智能体从区域级预警下钻到对象级研判，如学校、医院、养老院、低洼小区、地下空间、危化企业等。

| 字段名称 | 字段解释 |
|---|---|
| `object_id` | 重点对象唯一ID。 |
| `object_name` | 对象名称。 |
| `object_type` | 对象类型，如学校、医院、养老院、地铁站、地下空间、危化企业。 |
| `area_id` | 所属行政区或业务区域ID。 |
| `area_name` | 所属区域名称。 |
| `grid_id` | 所属网格ID。 |
| `address` | 详细地址。 |
| `longitude` | 经度。 |
| `latitude` | 纬度。 |
| `boundary_geometry` | 对象边界或影响范围，可存 GeoJSON。 |
| `responsible_unit` | 责任单位。 |
| `responsible_person_id` | 责任人ID。 |
| `emergency_contact_name` | 应急联系人姓名。 |
| `emergency_contact_phone` | 应急联系人电话。 |
| `population_capacity` | 最大容纳人数或服务能力。 |
| `current_population_estimate` | 当前估计人数。 |
| `vulnerable_population_count` | 脆弱人群数量。 |
| `vulnerability_tags` | 脆弱性标签，如低洼、地下空间、老人多、儿童多、危化品。 |
| `critical_assets` | 关键资产，如急诊入口、配电室、地下车库、化学品库房。 |
| `historical_risk_level` | 历史风险等级。 |
| `historical_incident_count` | 历史险情或灾情次数。 |
| `max_historical_water_depth_cm` | 历史最大积水深度。 |
| `special_plan_id` | 专项预案ID。 |
| `evacuation_route_ids` | 关联转移路线ID列表。 |
| `nearest_shelter_ids` | 关联避险安置点ID列表。 |
| `last_inspected_at` | 最近巡查时间。 |
| `current_control_status` | 当前管控状态，如正常、预警、已管控、已转移。 |
| `data_source` | 数据来源，如行业台账、GIS、网格系统。 |
| `updated_at` | 数据更新时间。 |

## 5. 个体与重点人群数据

用于支持重点人群叫应、上门确认、转移避险。该类数据应脱敏、分权限展示。

| 字段名称 | 字段解释 |
|---|---|
| `person_case_id` | 脱敏后的人员或家庭案例ID。 |
| `household_id` | 家庭或住户ID。 |
| `area_id` | 所属区域ID。 |
| `grid_id` | 所属网格ID。 |
| `location_level` | 地址精度级别，如精确地址、楼栋、网格、风险区。 |
| `location_hint` | 位置描述，用于救援定位。 |
| `longitude` | 经度，可按权限脱敏。 |
| `latitude` | 纬度，可按权限脱敏。 |
| `person_type` | 人群类型，如独居老人、残疾人、孕妇、慢性病患者、留守儿童。 |
| `risk_tags` | 风险标签，如一楼住户、地下室、危旧房、低洼院落、山洪危险区。 |
| `mobility_need` | 转移能力需求，如可步行、轮椅、担架、车辆、医护陪同。 |
| `medical_need` | 医疗需求，如吸氧、透析、定时用药、卧床护理。 |
| `caregiver_available` | 是否有照护人在场。 |
| `emergency_contact_id` | 紧急联系人ID。 |
| `responsible_grid_worker_id` | 负责网格员ID。 |
| `responsible_village_person_id` | 村社区责任人ID。 |
| `preferred_shelter_id` | 优先安置点ID。 |
| `transfer_priority` | 转移优先级。 |
| `last_contact_status` | 最近联系状态，如未联系、已联系、失联、已转移、拒绝转移。 |
| `last_contact_at` | 最近联系时间。 |
| `transfer_status` | 转移状态，如未转移、准备转移、转移中、已安置。 |
| `transfer_destination_id` | 实际安置点或目的地ID。 |
| `privacy_level` | 隐私级别，用于控制字段可见范围。 |
| `data_source` | 数据来源，如民政台账、社区台账、网格上报。 |
| `updated_at` | 数据更新时间。 |

## 6. 队伍、物资与装备数据

用于判断智能体生成的处置方案是否具备执行条件。

| 字段名称 | 字段解释 |
|---|---|
| `resource_id` | 资源唯一ID。 |
| `resource_name` | 资源名称。 |
| `resource_type` | 资源类型，如抢险队、车辆、抽水泵、冲锋舟、发电机、沙袋、无人机。 |
| `owning_unit` | 所属单位。 |
| `storage_location` | 常驻或仓储位置。 |
| `current_location` | 当前实时位置。 |
| `quantity_total` | 总数量。 |
| `quantity_available` | 当前可用数量。 |
| `status` | 状态，如可用、待命、已派出、维修、不可用。 |
| `task_capability` | 可执行任务类型，如排涝、巡查、搜救、转移、抢修、通信保障。 |
| `dispatch_authority_level` | 调度权限级别。 |
| `contact_person_id` | 负责人ID。 |
| `contact_phone` | 负责人电话。 |
| `estimated_arrival_minutes` | 到达目标地点预计时间。 |
| `assigned_task_ids` | 已关联任务ID列表。 |
| `remaining_capacity` | 剩余能力，如还能转运多少人、抽排能力剩余多少。 |
| `maintenance_status` | 维护保养状态。 |
| `last_checked_at` | 最近清点或检查时间。 |
| `data_source` | 数据来源，如物资仓库系统、队伍台账、现场上报。 |
| `updated_at` | 数据更新时间。 |

用于让智能体回答“转移谁、去哪、怎么走、谁负责、是否到达”。

| 字段名称 | 字段解释 |

| `shelter_name` | 安置点名称。 |
| `shelter_type` | 安置点类型，如学校、体育馆、社区中心、临时安置点。 |
| `area_id` | 所属区域ID。 |
| `address` | 地址。 |
| `longitude` | 经度。 |
| `latitude` | 纬度。 |
| `capacity_total` | 总容量。 |
| `capacity_available` | 当前可用容量。 |
| `current_occupancy` | 当前已安置人数。 |
| `open_status` | 开放状态，如未启用、准备启用、已开放、满载、关闭。 |
| `suitable_groups` | 适合接纳人群，如老人、儿童、残障人员、普通群众。 |
| `medical_support_available` | 是否具备医疗支持。 |
| `barrier_free_available` | 是否具备无障碍条件。 |
| `food_supply_hours` | 食品可支撑小时数。 |
| `water_supply_hours` | 饮用水可支撑小时数。 |
| `power_status` | 供电状态。 |
| `communication_status` | 通信状态。 |
| `manager_person_id` | 安置点负责人ID。 |
| `access_route_ids` | 可达路线ID列表。 |
| `route_risk_status` | 进出路线风险状态。 |
| `assigned_transfer_batch_ids` | 已分配转移批次ID列表。 |
| `last_confirmed_at` | 最近确认时间。 |

| 字段名称 | 字段解释 |
|---|---|
| `transfer_batch_id` | 转移批次ID。 |
| `source_area_id` | 转出区域ID。 |
| `person_case_ids` | 转移人员脱敏ID列表。 |
| `vehicle_resource_ids` | 使用车辆资源ID列表。 |
| `escort_person_ids` | 陪护或护送人员ID列表。 |
| `destination_shelter_id` | 目标安置点ID。 |
| `route_id` | 转移路线ID。 |
| `departure_status` | 出发状态。 |
| `arrival_status` | 到达状态。 |
| `last_confirmed_at` | 最近确认时间。 |

| 字段名称 | 字段解释 |

| `incident_type` | 事件类型，如城市内涝、山洪、人员被困、工程险情。 |
| `occurred_at` | 事件发生时间。 |
| `reported_at` | 实际报送时间。 |
| `deadline_at` | 应报送截止时间。 |
| `report_to` | 报送对象，如县防指、市防指、行业主管部门。 |
| `report_channel` | 报送渠道，如政务平台、电话、传真、工作群。 |
| `casualties_summary` | 人员伤亡情况。 |
| `missing_people_summary` | 失联或失踪人员情况。 |
| `trapped_people_count` | 被困人数。 |
| `transferred_people_count` | 已转移人数。 |
| `sheltered_people_count` | 已安置人数。 |
| `infrastructure_damage` | 基础设施损毁情况。 |
| `economic_loss_estimate` | 经济损失估计。 |
| `current_response_actions` | 当前已采取处置措施。 |
| `next_planned_actions` | 下一步计划动作。 |
| `approval_unit` | 审核或签发单位。 |
| `approval_person_id` | 审核或签发人员ID。 |
| `publish_status` | 发布状态，如草稿、待审、已发布、已撤回。 |
| `public_message_id` | 关联公众发布消息ID。 |
| `updated_at` | 数据更新时间。 |

| `event_id` | 关联防汛事件ID。 |
| `overall_status` | 总体状态，如正常、关注、预警、管控、停运、险情。 |
| `flood_exposure_level` | 受淹或受洪水影响等级。 |
| `water_intrusion_status` | 是否进水、倒灌或受浸。 |
| `access_status` | 外部通达状态，如通畅、拥堵、受阻、封闭。 |
| `internal_operation_status` | 内部运行状态，如正常、部分受限、停运、转移中。 |
| `power_status` | 供电状态。 |
| `backup_power_hours` | 备用电源可支撑小时数。 |
| `water_supply_status` | 供水状态。 |
| `communication_status` | 通信状态。 |
| `people_exposed_count` | 当前受影响或暴露人数。 |
| `vulnerable_people_count` | 当前受影响脆弱人群数量。 |
| `resource_need_summary` | 所需资源摘要。 |
| `external_support_needed` | 是否需要外部支援。 |
| `evacuation_needed` | 是否需要转移。 |
| `shutdown_needed` | 是否需要停运、停产或关闭。 |
| `risk_flags` | 风险标记，如断电、倒灌、泄漏、通道中断、病患转移。 |
| `recommended_actions` | 系统或人工建议动作。 |
| `responsible_unit` | 责任单位。 |
| `responsible_person_id` | 责任人ID。 |
| `status_source` | 状态来源，如现场上报、行业系统、视频识别、人工确认。 |

| `updated_at` | 数据更新时间。 |

## 13. 潜在的额外可用数据

这些数据不是最小闭环必需，但可以显著增强智能体的主动发现、核验、推演和复盘能力。

| 字段名称 | 字段解释 |
|---|---|
| `extra_data_id` | 额外数据记录ID。 |
| `data_type` | 数据类型，如无人机影像、视频识别、舆情、人流热力、交通导航、水动力模型。 |
| `source_platform` | 数据来源平台或系统。 |
| `collection_time` | 数据采集时间。 |
| `area_id` | 关联区域ID。 |
| `location` | 关联位置。 |
| `media_url` | 影像、图片、视频或文件地址。 |
| `analysis_result` | AI或人工分析结果。 |
| `confidence` | 分析置信度。 |
| `detected_incident_type` | 识别出的事件类型，如积水、车辆滞留、人群聚集、道路中断。 |
| `detected_object_count` | 识别到的对象数量，如车辆数、人员数、积水区域数。 |
| `public_opinion_sentiment` | 舆情情绪，如平稳、焦虑、恐慌、谣言风险。 |
| `hotspot_keywords` | 舆情或群众反馈热点关键词。 |
| `population_density_estimate` | 人流密度估计。 |
| `traffic_delay_minutes` | 交通延误时间。 |
| `model_output_json` | 水动力模型、扩散模型或风险模型输出。 |
| `linked_event_id` | 关联事件ID。 |
| `linked_object_id` | 关联重点对象ID。 |
| `verification_status` | 核验状态，如待核验、已核验、疑似误报。 |
| `data_quality` | 数据质量，如正常、模糊、缺失、过期。 |
| `updated_at` | 数据更新时间。 |

典型可接入数据包括：

- 无人机巡查影像：用于核查堤防、水库、山洪沟、低洼区、道路中断。
- 视频AI识别：用于识别积水、人车滞留、井盖异常、交通中断。
- 舆情数据：用于发现群众集中反映点、谣言风险、恐慌情绪。
- 手机信令或人流热力：用于判断景区、学校、车站、商业区人员聚集。
- 交通导航数据：用于判断拥堵、封路、可替代路线。
- 水动力模型数据：用于推演积水扩散、漫溢路径和到达时间。
- 高精度地形和三维模型：用于支撑数字孪生空间表达。
